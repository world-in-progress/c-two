## 需要先修正的不变量

**R01 · P1 · Buddy 释放检查不能证明正在释放的是原分配块。** [pool.rs:815](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/pool.rs#L815) 根据传入尺寸计算释放层级，[buddy.rs:416](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/alloc/buddy.rs#L416) 只检查当前节点和祖先是否已经空闲。位图的“0”同时表示已分配节点及被父块占用的子节点，因而无法拒绝释放活父块的一个子区间。IPC 响应释放链也使用 wire 尺寸，[client.rs:490](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-ipc/src/client.rs#L490) 的段内跨度检查不提供精确分配证明。这不是正确尺寸释放一定失败，而是 API 接受错误释放后破坏了仍存活分配的隔离。

Host 在仓库外直接编译当前 `buddy.rs`、`bitmap.rs`、`spinlock.rs`，只操作分配元数据，未生成重叠 Rust 切片：8192 字节数据区分配 8192 后，以 4096 对应层级释放 offset 0，得到 `Ok(())`、`alloc_count: 1 → 0`、`can_retire: true`；再分配 4096 返回 offset 0，与原活块重叠。目标应是精确的 Free/Split/Allocated 或 allocation order 元数据，释放必须匹配真实活块后才能修改位图和计数。当前饱和递减也不能代替这一证明。保留 [double-free 测试](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/alloc/buddy.rs#L771)、合并后重复释放和 [世代退休测试](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/pool.rs#L2228)；增加子区间释放被拒、计数不变、分配不重叠的行为用例。可信度：已用当前分配器源码复现；尚未做完整 IPC 端到端复现。

**R02 · P1 · 公有坐标句柄与共享池借用允许 safe Rust 请求重叠可变切片。** [MemHandle](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/handle.rs#L13) 可以用相同坐标构造两份，[handle_slice_mut](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/pool.rs#L1214) 接收 `&self` 和各自的 `&mut MemHandle`，随后返回 `&mut [u8]`。两个独立句柄的借用约束互不关联；校验世代和映射跨度不能建立唯一写所有权。目标是区分不可信的入站坐标与 allocator 创建的私有拥有型句柄，并把切片借用绑定到唯一 allocation owner；单独增加一处边界检查不能修复别名关系。独占 pool 借用只能解决同一 pool 的一部分问题，还应审查重复打开同一 backing 的拥有关系。

保留 [正常读写](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/pool.rs#L2924) 和 [trim 后释放原分配](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/pool.rs#L2990)；把公有伪造句柄测试迁到 RawRef 接纳边界，句柄不透明后删除 [手工构造形状测试](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/handle.rs#L103)，用编译失败测试约束非法借用。可信度：高，来自公开 safe API 和借用关系的静态证明；没有执行故意制造别名的程序。尝试使用现存 rmeta 做独立编译检查时依赖不可解析，该尝试不计为通过证据。

**R03 · P1 · shutdown 把发送前失败和发送后结果不确定合并为重试。** [exchange](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-ipc/src/control.rs#L58) 将 connect、write、ACK/read 和超时失败折叠为 `NoReply`；[shutdown 循环](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-ipc/src/control.rs#L284) 随后重连并重发。旧实例收到 shutdown、回执丢失、同地址被新实例绑定时，后续重试可能停止新实例。目标是明确 `NotSent` 与 `DispatchUncertain`：一旦尝试发送控制写，失去确认就返回不确定结果，不跨新实例重发；需要继续观测时绑定原实例身份。保留 ACK 只证明 initiate 的语义。改写 [shutdown_ack_only_proves_initiation_and_retries_dropped_exchange](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-ipc/src/control.rs#L572)，分别验证安全的发送前重试、发送后丢 ACK 和实例更替。可信度：高，发送与接收调用链已复核，竞态未动态复现。

**R04 · P1 · 路由开放令牌未绑定具体登记，且不能阻止 OwnerMissing 后重开。** [RouteAdmissionToken](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L278) 已经是消耗型令牌，但只包含 route name 与 shutdown generation；[open_route_admission](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L930) 按名称寻找当前路由。同一服务器代际内，A 移除后登记同名 B，A 的旧令牌可以打开 B。另一个交错是 [Core relay 登记](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/runtime/c2-core/src/session.rs#L1292) 持有令牌时触发 [OwnerMissing](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/runtime/c2-core/src/owner_bound.rs#L212)；[close_business_admission](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L1525) 不推进该 generation，旧令牌仍能重开 scheduler/catalog，[派发路径](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L2624) 不再检查全局关闭标志。

目标是令牌绑定 route UID/登记代际，并让“开放对应的 Closed(RegisterCommitted)”与 OwnerMissing/关闭成为同一个状态事务。不能只把令牌改成 move-only，因为它已经如此。用实际行为替换 [仅检查开放 API 签名的测试](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L6678)；保留 [shutdown generation 栅栏](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L5275) 和 [正常开放行为](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/catalog.rs#L640)，补旧令牌不能打开替换路由、OwnerMissing 后 callback 不执行。可信度：高，静态时序已复核；并发时序尚未运行复现。

## 已定位的实现收敛点

**R05 · P2 · SHM attach 在安全 open 边界缺少完整布局接纳。** [BuddySegment::open](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/buddy_segment.rs#L56) 调用 unsafe attach；[attach](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/alloc/buddy.rs#L219) 只核对 magic/version，随即用共享 header 的 data_offset、min_block、max_levels 计算大小和 [bitmap 指针](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/alloc/buddy.rs#L514)。有效 magic/version 不足以证明几何合法。应在安全 open 边界验证完整 header、bitmap 和数据区范围，形成不可变 ValidatedLayout；创建与附着共享布局计算权威。保留 OS 映射长度、世代及锁保护，在 attach 边界增加畸形布局拒绝用例，避免把检查散落到每次 alloc/free。可信度高，畸形共享段未动态构造。

**R06 · P2 · ResponseBuffer 的 export 检查在 owner 锁之外。** [release](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/sdk/python/native/src/core_ffi.rs#L355) 先检查 exports，再获取 inner 锁；[getbuffer](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/sdk/python/native/src/core_ffi.rs#L424) 在 inner 锁内创建导出并增加 exports。在声明支持自由线程的扩展中，检查 0 与释放之间可能出现新导出，使检查失去约束。目标是在同一 owner 状态锁内检查导出并完成释放。当前 [HeldResponse](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/runtime/c2-core/src/lifetime.rs#L64) 保留复制 Vec，且 Py_buffer 持有对象，现有证据不支持立即 UAF；报告的是释放栅栏和租约状态问题。保留真实 buffer 生命周期测试，用受控并发验证导出与释放互斥，不能以源码中出现检查函数作为证明。可信度高，竞争未动态复现。

**R07 · P2 · release_handle 吞掉失败后消费唯一句柄。** [release_handle](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/pool.rs#L1243) 用 `unwrap_or(FreeResult::Normal)` 将锁竞争耗尽、poison 等释放失败呈现为成功。目标是返回真实释放结果，失败时保留 owner 并明确区分竞争可恢复与 poison/dead-holder 等 backing 拒绝；沿用 reassembly 的失败保留模式，不能承诺所有失败靠普通重试恢复。保留 [竞争拒绝不改变分配](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-mem/src/alloc/buddy.rs#L916) 与 trim 释放测试，增加失败传播和可重试验证。仓内只找到测试调用，因此这是已证实的公开 API 缺陷，尚未证明现有业务链受影响；也可在确定支持范围后撤去这项多余公开面。

**R08 · P2 · 配置先解析低优先级来源，再用高优先级覆盖。** [server resolver](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-config/src/resolver.rs#L619) 和 [client resolver](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-config/src/resolver.rs#L699) 先解析环境，再写显式 override；有效 override 无法屏蔽同字段的 `not-a-number` 环境值。应按字段先选最终来源，再解析与验证一次。扩展 [优先级测试](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-config/src/resolver.rs#L1142)、[server override](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/sdk/python/tests/unit/test_ipc_config.py#L196)、[client override](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/sdk/python/tests/unit/test_ipc_config.py#L400)，覆盖坏低优先级值；保留 [call limits 已有正确语义](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-config/src/resolver.rs#L1970)。此外 [空字符串解析](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-config/src/resolver.rs#L1020) 会把数值/布尔显式空值降为默认值，如预算恢复默认、pool_enabled 恢复 true。该行为已确认，但统一为空值报错属于策略决定；不要波及已有明确“空值禁用”语义的 env_file、relay anchor。

二轮定性调整：winner-first 是有合理先例的解析策略收敛，但历史 IPC 规范也要求 numeric parse failure 返回错误，未明确被覆盖坏值必忽略。因此改造需显式记录错误行为变化，不能当成纯等价删减。

## 需要先完成设计或补证的候选

**C01 · 私有、不可变的合同身份。** [ExpectedRouteContract](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/foundation/c2-contract/src/lib.rs#L30) 的公开字符串字段允许内部再次构造非法值，导致 release、Core client、IPC acquisition 和 wire projection 反复验证/克隆。目标是边界 TryFrom 接纳一次、字段私有且不可变，wire encoder 借用投影。这样可以删除相同本地值的语法重验，但不能删除远端 wire 校验、当前 route UID/revision、server_instance_id 或重连身份检查。应先清点受支持的 Rust 构造 API，再实施 0.x clean cut。

**C02 · 从接纳开始持有请求租约，并共享可执行登记实体。** [RequestData](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/dispatcher.rs#L62) 的 SHM 变体没有自动释放，[多个提前返回](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L2584) 和 chunk 分支手工 cleanup。让 request lease 从接纳持有到 dispatch，成功时显式移交，才能删除各分支的重复释放；本轮没有证明现有分支一定泄漏。[业务准入](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L2629) 又从 Catalog 克隆完整 RouteRecord 后丢弃，再查 Dispatcher。可先引入借用式准入结果，再让目录投影和执行对象共享登记实体；两次读取间有 await/替换窗口，当前第二次身份比较不能直接删。保留 stale token-before-callback、同名排空、单赢家、取消/abort fence、held/borrowed 生命周期测试。

**C03 · Chunk assembly 与 pending permit 应属于同一代对象。** [GC](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L624) 先收集不存在于 registry 的 key，释放锁后按 key 删除 pending；[插入/完成路径](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L3644) 在两张表维护平行事实。旧 pending 被另一条路径移除、同 key 新 generation 插入的交错可能使清扫误删新许可。应由同代 assembly 拥有 route permit，GC 按实例身份释放，完成后移动所有权，再删除冗余 route/method 对照。这个交错尚未受控复现，列为待验证风险，不当作已复现缺陷。保留 [assembler timeout](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L7981)、[回滚](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L8431)、[chunk GC](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-server/src/server.rs#L8705)，先加入屏障控制的代际交错验证。

二轮确认：loader 明文承诺 context symbols 追加后旧 ABI 3 仍有效；Windows、注入连接和独立查询仍有旧能力用途。SyncClient 预分配还能直接 fill 并在失败/panic 时精确释放，普通 bytes 调用不是完整替代。0.x 可明确退役，但不能维持同一兼容承诺却改成必需新符号。

**C06 · EOF 契约已明确，严格成功策略另作设计。** 二轮查明 [round_complete](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-local/src/lib.rs#L191) 明确定义为该 batch 到达目录 EOF，因此它与局部 io_errors 共存合法；撤回“完成契约尚未核实”的表述。[ReadDir 错误](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-local/src/unix_managed.rs#L1715) 的覆盖可信度及 [CLI](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/cli/src/endpoint.rs#L198) 是否应增加严格成功条件仍可讨论，但会改变公开退出语义。若新增枚举失败状态，应贯穿所有 batch，验证候选错误、枚举错误、跨 batch 累计、namespace 替换、中断和 EOF。SweepLease 控制并发维护资源，当前没有删除依据；保留未知 endpoint 的保守清理边界。

**C07 · 先封闭适配协议，再删除形状兼容。** [unpack_resource_result](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/sdk/python/src/c_two/transport/server/reply.py#L19) 接受单元 tuple、None、裸 buffer，常规 transfer wrapper 返回固定二元组，但继承方法、自定义契约和公开适配器是否全部保证该形状还需核实。因此只确认 R33 的 wrap_error 可删，不能直接把这里的所有兼容形状判为死代码。R10 的 registration plan 应产生确定方向的调用闭包，消除 [每次调用判断 direction](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/sdk/python/src/c_two/crm/transferable.py#L493) 后，再统一返回协议。Relay 的 [header/逐行 namespace](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-http/src/client/control.rs#L162) 与 [legacy None](https://github.com/world-in-progress/c-two/blob/2ffe356f15d8ce1c8fad9e08a91ffff808d34dad/core/transport/c2-http/src/client/relay_aware.rs#L201) 也应收敛为明确协商结果；保留没有本地 capability 时的合法 HTTP-only 路径，不用新增 fallback 维持旧组合。

尚不足以支持删除的具体分支包括服务端 data_ptr 失败处理、peer geometry/clamp、外部 raw NumPy/pointer 逃逸的约束，以及跨进程 release/retirement 防护。它们需要完整故障类别和所有权证据，本轮未将其列入可直接删减项。

## 验证记录与建议顺序

本轮做了四项有边界的实际检查：R01 用固定提交的原始 allocator/bitmap/spinlock 编译最小程序，确认错误子块释放与重叠分配；R23 提取原 start 函数，确认有限 timeout 被丢弃；T01 在原测试函数中替换文本输入，确认两个源码词串测试接受全注释 YAML；T04 以自有沉默子进程调用原读取函数，确认 20 ms 预算延迟到约 281/282 ms 才退出，随后均完成子进程回收。试验文件放在本轮临时目录，未更改生产实现、现有测试或用户数据。除这四项外，本报告的发现主要是静态源码和调用链证据。

R01 的实际输出如下；程序只比较分配坐标，没有读取/写入 payload 或创建重叠切片：

```text
parent_offset=0 parent_size=8192 wrong_free=Ok(()) count_before=1 count_after=0 can_retire=true child_offset=0 child_size=4096 overlap=true
```

R02 的现存 rmeta 独立编译探针失败于依赖解析，未作为通过证据。R03/R04 的竞态、R06 的自由线程竞争、C03 的 GC 交错、Windows 运行结果、外部 C/npm/Rust API 消费者，以及所有性能收益均尚未动态验证。源码显示重复分配、查找或解析，不足以直接报告吞吐提升或可删除的总行数。

建议先修 R01–R04 的所有权与状态不变量，并用行为测试覆盖；随后处理 R06–R08 等释放/配置语义问题，同时清除 R27/R33/R37 这类消费者或决策用途已明确消失的代码。再集中建立 RegistrationPlan、私有合同身份、唯一配置快照和请求/响应 owner，随之删除重复检查及伪造非法内部状态的测试。数据流和 GC 的性能改造应在状态边界稳定后用实际调用链测量，保留 Rust/Python portable direct/relay、生命周期和 Windows 等真实保障。

本轮没有把外部 wire 长度/UTF-8/tag/合同校验、generation/nonce/ACL、SHM 锁/PID/poison、预算退款、绝对 deadline、动态 late route、idle eviction、重连身份、发送后不确定性、no-replace 发布和 FastDB invalidate-before-release 判为无意义防御。这些机制保护的输入或时序仍真实存在；瘦身的验收标准应是少一份状态、少一条不可达退路或少一次重复工作，同时保留可观察的正确行为。
