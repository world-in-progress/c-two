## 三项修复

- 基础 wheel 的 Python 运行时依赖为空；`c-two[fastdb]` 固定 `fastdb4py==0.2.2`。普通契约、注册、连接、调用及异常包装不加载 FastDB/NumPy；实际使用 FastDB 载荷而缺依赖时明确提示该扩展。精确 pin 选择本次验证的 0.x 绑定，不自动接纳未来接口。原生 FastDB Core/Rust 依赖仍单独固定 0.2.1。
- 出站 IPC 的 DISCONNECT 写入与 ACK 共用每连接最多 100 ms 的窗口，仍受原总体期限约束。保留本地任务、pending、writer、pool 和 lease 屏障，不增加后台等待线程。新增 `ipc_clients_abnormally_closed` 及 `ipc_client_close_details`（`address`、`reason`）；旧字段继续表示本地收尾，服务端调用排空和 timeout 含义不变。
- `register()` 在创建服务前拒绝实现类上未由 CRM 声明的 `@cc.on_shutdown`，不静默忽略。有效契约钩子仍执行一次；静态扫描不执行无关 property。独立审查指出的 marker-property 反例已先红后绿验证并修正。

## 同环境测量

macOS arm64，CPython 3.13.3。比较 PyPI 发布版 0.7.4 与本次源码构建的 0.7.5 基础 wheel；各用 5 个新进程，使用 `ps` 读取当前 RSS，中位数如下。脚本同时执行同进程和真实 IPC 调用。

| 阶段 | 0.7.4 | 0.7.5 |
| --- | --- | --- |
| 仅导入 RSS | 29.31 MiB | 29.31 MiB |
| 定义契约并完成最小调用后 RSS | 44.77 MiB | 32.67 MiB |
| 完成调用后 `fastdb4py` / `numpy` 已加载 | 是 / 是 | 否 / 否 |
| SIGSTOP 对端后默认关停 | 29.0026 s | 0.1023 s |

调用后 RSS 减少 12.09 MiB。0.7.4 的加载触发点在契约定义阶段，纯导入本来就没有加载这两个模块，不能将纯导入内存宣称为本次收益。扩展已安装的 0.7.5 环境另测普通调用，也未加载二者。冻结对端结果包含准确地址和 `disconnect_ack_timeout`；本地完成仍如实返回。

## 契约、ABI 与尚未验证的部分

实际读取当前 hey-my-buddy 的 `BuddyControl`、`BuddyWait`、`ExecutionLive`，以正式模块名比较发布版与候选：完整 descriptor、CRM ABI hash、signature hash 均相同。用户列出的受保护 Python 接口签名也相同。**这三个修复本身不要求 hey-my-buddy 修改 CRM 契约版本**，没有改变 C/FFI ABI 或 wire。

但整包包含此前已接受的 R01：相对已发布 0.7.4，使用 SHM 3、IPC 12、C/FFI ABI 5，不兼容旧格式。通信进程及 c3 必须成套升级；这与业务 CRM 指纹是否变化是两回事。低层迁移见[发布说明](../releases/0.7.5.md)。
