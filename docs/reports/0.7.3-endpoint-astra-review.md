## 五轴审查

### Correctness

配置与命名：`core/foundation/c2-config/src/local.rs` 删除布局字段、版本目录、完整路径 `sun_path` 检查；默认最终目录为 `/tmp/c2-<uidhex>`。自定义目录直接追加 32 个小写十六进制字符，取逻辑 server id 的 SHA-256 前 16 字节。namespace id 保留 backend、root、OS scope 的长度分隔哈希；默认与显式相同默认目录得到相同 context。Windows 使用当前 logon scope 与同一短标识，拒绝 Unix root；没有新增内部布局编号或旧路径选择开关。

目录：`core/transport/c2-local/src/unix_managed.rs:380` 附近只在最终 root 等于平台默认时允许创建；自定义 root 只打开和验证。严格当前 UID/0700 校验仍在，未引入 chmod、递归 mkdir 或应用目录删除。目录改名/替换后的 inode 与命名检查仍生效。默认目录的父目录不再被误当作私有 namespace。

连接：`core/transport/c2-local/src/unix.rs:15–48` 持有已验证目录，通过统一启动函数创建 socket，交给调用方 Tokio reactor 等待 writable 并读取 SO_ERROR，再核对目录仍指向同一对象。失败与取消通过 Rust 所有权释放 socket 和目录。`unix_common.rs:628–673` 的 macOS 专用短时线程只设置自身 cwd 并启动一次非阻塞连接；工作完成及 panic/spawn 失败均有拥有型描述符负责释放，未在调用方或共享池线程切 cwd。Linux 通过持有的 `/proc/self/fd/<fd>/<short-name>`；probe 消费同一目录相对机制，pending/不可判断只否决清理。

凭据：Unix 默认/自定义统一既有 schema 3，删除 schema 2 默认 root 重建。编码、解码共用 `ENDPOINT_CREDENTIAL_MAX_BYTES = 32 * 1024`；CLI `cli/src/endpoint.rs:276–283` 从 Core 引入同一常量并限定读取。Windows schema 1 保留；root、namespace id、完整 address、incarnation 与 inode 身份仍验证。

### Readability and simplicity

删去旧路径层、layout 投影及 schema 2 特例后主路径更直接。新增 Node 原生桥接确实需要独立的异步工作和 fd owner；这些对象分别承担 context、待完成连接、交接结果的生命周期，没有发现为兼容旧目录而新增的冗余机制。现存 `legacySymbols` 查询分支来自基线，本次没有扩展为旧路径连接 fallback；新的 Unix 默认连接在缺少原生能力时明确失败。

除上列两个注释/文案问题，没有发现应阻塞的复杂度问题。

### Architecture

`c2-config` 仍是路径与 namespace 派生的单一所有者；`c2-local` 拥有目录验证、操作系统寻址及连接完成；FFI 仅将拥有型 Unix stream 交给外部事件循环，TS 不自行拼接 Unix socket 地址。`c2-mem-ffi` 新增对 `c2-local` 的 Unix 条件依赖是传输投影需求，未将底层端点机制复制到 SDK。

完整路由契约、握手 identity、server incarnation、Relay namespace 比较仍由既有 Core/transport 层处理。本次对 Relay 的主要代码差异为测试及 fixture，不绕过身份检查。Python 移除 `layout` getter，未增加 SDK 路径派生或 cwd 操作。

### Security and ownership

专项 Node 边界结论：

1. `core/transport/c2-local/src/lib.rs:332–352` 复用原生 deadline 与 `into_std()`，将 stream 从 Tokio 交给外部事件循环；FFI 在 `src/lib.rs:530–568` 初始化失败输出、保留调用期间 context，成功后才 `into_raw_fd()`。Windows 分支返回 InvalidArgument，Unix 依赖与 fd 操作均有平台条件。
2. N-API `node_c2_mem_ffi_loader.c:891–906,1047–1108` 在排队前增加 active_connects，创建 receiver 强引用，直到 complete/dispose 才释放；close/finalize 在 active_connects 非零时不销毁原生 context。worker 只读取被保留的 context 指针；状态与引用释放在完成回调序列中处理，未发现关闭线程与 worker 的指针释放竞态。
3. fd 从 work 转入 `NativeSocketFd` 时将 work fd 置 -1；`takeFd`、显式 close 将 owner fd 置 -1，finalizer 只关闭仍拥有的 fd。对象创建、Promise 交接失败以及关闭后完成均有释放分支。重复 close 与已转移后 close 不会关闭被 Node 采用的描述符。
4. TS `index.ts:575–595` 另持 context lease 跨越 await，结果回来后检查 connector 是否已关闭；关闭期间完成的结果在 finally 中释放。采用 fd 后由 Node Socket 持有；构造失败有 closeSync，后续包装失败由外层 catch destroy socket。
5. 32 位 fd 是 Unix 文件描述符投影，不把 Windows HANDLE 截断成 fd。Windows TS 默认路径继续走 Named Pipe，原生 Unix close 在 Windows 不执行。

nonce coordinator、原始 gate inode 固定、listener lease、完整逻辑地址记录、incarnation 及精确 inode 清理检查未被本次路径扁平化删除。probe 的失败不会单独授权 unlink。没有发现用户目录或无关文件被纳入回收的新增路径。

### Performance

新 macOS 线程只发生在建立物理连接和维护 probe，不发生在每次 RPC；pending 由 reactor 驱动，不在该线程等待。Node 在 N-API worker 上建立临时 current-thread Tokio runtime，连接成功后转交 Node。这个代价与明确的跨事件循环边界一致，没有性能基准支持吞吐或时延提升的声称。

需要保留的限制：Node close 标记失效并在 work 完成时释放，不会主动取消已执行的原生连接；原生等待上限为 5 秒，libuv 队列等待时间不包含在该原生期限中。高并发失败连接可能占用 libuv worker 并排队。现有接口没有承诺 connector.close 同步完成 pending I/O 回收，因此这是性能/完成时机边界，未列为正确性阻塞项。
