# 0.7.4 connection-pool FD regression validation

[简体中文](0.7.4-fd-leak-regression.zh-CN.md)

The downstream handover documents socket accumulation after idle eviction in 0.6.0: removing a client left a detached receive task holding the connection. The current 0.7.4 runtime explicitly closes retired clients and aborts receive work on drop. This follow-up adds real-connection tests without changing production code.

## Original probe

The Python 3.13 native module was rebuilt from `46480adf7424f794482fc761a2c8ec53dd28323b`. An unchanged copy of the original `run.py` ran with a private endpoint directory through `main30 → idle62 → idle62 → bgidle70 → idle130 → main30`. It finished in 341 seconds with exit code 0 and `no growth`.

Both processes held five Unix sockets after every phase. The server baseline was four and returned to four after client exit: one business connection survived, with no accumulation across idle reconnects. The background phase completed 34 calls. All six files in the original handover directory retained their hashes, and the probe's private endpoint directory was removed.

## Regression gates

Four cross-platform tests in `core/transport/c2-ipc/src/pool.rs` exercise expiry on acquire, explicit sweep, exact discard with replacement protection, and close_all across active/idle clients followed by reconnect. They retain the old client Arc and require actual peer EOF. A disconnect signal is acknowledged without treating it as closure. PING/PONG and live-connection counts prove retained and replacement connections remain usable.

`sdk/python/tests/integration/test_client_pool_idle_cleanup.py` uses separate server/client processes. The persistent client performs context-managed calls and then idles for 62 seconds twice. The server remains at `baseline + 1`, returning to baseline on client exit. Counts use Linux `/proc` or macOS `lsof`; Windows exercises the same retirement mechanism through the Rust Named Pipe tests. The 240-second test marker overrides CI's default 30-second timeout. Tests own their processes/endpoints and keep the normal parallel harness.

Local results: all four new Rust cases passed; all 199 c2-ipc tests passed with four threads; the SDK test, formatting and diff checks passed. Windows execution belongs to the Windows Native gate for this patch; local results do not replace platform evidence.

## Negative control

A separate temporary source tree, Cargo target and Python environment omit retired-client close and empty IpcClient Drop. This restores removal-without-close and detached receive ownership. All four Rust tests failed while waiting for actual peer EOF (exit 101). The SDK test saw six sockets where five were expected after its first 62-second idle and failed on growth (exit 1). This is a mechanism-level control, not a claim that unchanged 0.6.0 was rerun.

The first negative SDK build failed because the local C++ standard headers were not found. That failed execution remains recorded. Only this temporary build received the current SDKROOT and standard-header path; its successful rebuild then produced the functional assertion failure above. A compiler error was not counted as negative-test evidence, and completed positive checks were not repeated.

Astra max found no blocking source-review issue in the fixed patch. Source, native, patch, mutation and output hashes are in the [machine record](evidence/0.7.4-fd-leak-regression.json). Raw outputs remain in `/tmp/c2-074-fd-regression`. Merge and publication of PR #180 remain on hold.
