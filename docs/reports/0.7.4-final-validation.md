## Relay capacity response

Capacity refusal is fixed before business admission. For valid known-length requests without Expect, the handler discards transport frames within the declared length and one two-second deadline. It does not aggregate or decode the payload, invoke the resource, or retry admission. Releasing A's capacity while rejected upload B is being disposed does not admit B. Expect and unknown-length rejected bodies are not read; read faults, length mismatch and timeout preserve the original refusal.

Completed valid eager uploads in the real SDK gates receive canonical HTTP 502 / code 717 / envelope `pre_dispatch`, with no business callback. If a faulty or incomplete transport prevents response delivery, the existing client wrapper can report `DispatchUncertain`; the server's rejection decision does not prove the client received it. There is no new global rejected-handler concurrency cap, and native forwarding drain does not constitute a barrier for all HTTP buffers. See the [configuration guide](../configuration.en.md).
