They verify the original archives, internal hashes, strict 18-row Rust/Python
and 12-row TypeScript native receipts, and ordinary/non-administrator wheel
lifecycle and cleanup receipts before staging the tested files. Publication
rechecks staged bytes and performs no rebuild.

The native matrices bind each runner's own native c3 binary. The release c3
binaries bind the separate Release Candidate wheel and non-administrator
consumption receipts; these are distinct builds and their hashes are not
interchangeable.

## Installed public package check

The public CPython 3.13/macOS ARM64 C-Two wheel, official FastDB 0.2.1 wheel,
and macOS ARM64 c3 executable were downloaded, hashed and consumed by
`tools/ci/windows_wheel_smoke.py` in a new environment outside the checkout.
The test confirms package origins and exact input archives, direct IPC and
HTTP relay calls with a 1 MiB portable payload, held-view invalidation,
four borrowed-input invalidations, and orderly host shutdown. All child
processes exit and the temporary environment is removed.

The public Windows x64 c3 executable and checksum were also downloaded and
matched against the release plan. That binary was not executed on the macOS
host. Windows runtime evidence comes from the hosted Server 2022/2025 jobs.
Windows 11 desktop, Windows ARM64 and Windows services are outside this
validation.

The [retained summary](evidence/0.7.1-published-release-validation.json) records
the exact consumer file hashes and results. Earlier failed CI runs remain
failure evidence; the successful runs above establish the released source.
All 36 implementation delegations have Host conclusions: 33 accepted,
one failed and two cancelled with their original outcomes retained.
