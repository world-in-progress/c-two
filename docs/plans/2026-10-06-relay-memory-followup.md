# Relay 内存适配补齐

状态：本轮实现与验收完成。用户于 2026-10-06 批准补齐 relay 容量错误处理、内存配置入口与真实回归测试；HTTP 缓冲预算、背压和响应消费生命周期另行设计验收。本轮基线为 `b75e4d569fe7812edc0e70d88fbc306801529e01`，不推进 PR、合并或发布。

## 目标与边界

RelayState 拥有一份不可变的已解析上游 IPC 策略和对应共享预算；所有数据面连接及重连使用它。Rust c2-config 继续拥有代码覆盖、进程环境、.env 与默认值的解析和验证。容量拒绝是单次调用的失败；传输确实损坏时才关闭连接。服务端可能已执行的请求继续返回 702 和 dispatch_uncertain，禁止重放。既有路由、端点身份、合约校验及 buddy → dedicated → checked chunk → 接收端文件后备顺序保留。

## 阶段与验收

1. 配置接入：RelayConfig 携带 `upstream_ipc: ClientIpcConfig`；原生 resolver 用现有 client IPC 覆盖与环境解析得到它，RelayState 用同一值建立预算与客户端。CLI 提供相关预算/buddy 覆盖和 dry-run 结果。验证默认、代码/CLI 优先级、环境/.env、零预算、非法组合及真实客户端投影。禁止另造默认表或全局策略缓存。
2. 压力和生命周期：复现重组容量拒绝导致上游连接被驱逐的问题，修正分类，验证两个并发调用互不误伤、702/dispatch_uncertain、无重放、ping 和后续调用继续可用。增加多个真实 upstream 共享总额、重连不重置额度、取消/关闭后的真实退款检查。对重连取消卡住和未确认关闭仅在定向复现后修复，不用推测扩展实现。
3. 独立审查与整体验证：检查固定产物、关键差异与反例；运行受影响的 config、relay、CLI 测试和跨语言 relay 门禁。复用独立 CI 验证分支进行 Windows 验证，记录实际源码和产物，不更改旧收据。已通过且未受影响的检查不重复执行。
4. HTTP 后续设计：明确 C-Two 自有 HTTP 缓冲的聚合预算、准入/背压、超时及 Body 消费/断连的释放责任；区分 IPC 后备、SDK/FastDB 堆和进程 RSS。给出慢上传、慢下载、断连和错误响应的验收条件。本阶段交付设计，不把 HTTP 分片发送说成有界流式内存。

每个实现阶段先交付可独立审查的 Buddy 产物，由 Host 检查并整合；测试/等待使用 command 任务与低成本监控。最终记录本轮结果、未执行环境和剩余设计边界。
