## T9 追加设计：连接期限

用户追加的[下游会话](codex://threads/01a0ffef-8e72-7452-95f0-e587539f5ff3)在服务暂停后，首次 `cc.connect` 超过 3 秒，尚未进入 100 ms 业务调用。Host 使用已核验的公开 0.7.3 在私有端点复现：首连 3 秒仍等待，5.004 秒由固定握手保护返回错误；复用连接的路由查询 3 秒仍等待，恢复服务后才返回。探针自有服务正常退出、无端点文件残留。3 秒不是库承诺的连接期限；实际缺口是业务调用期限不覆盖连接、公开 API 没有可选连接总预算，路由控制等待也未被该预算约束。

接口为 `cc.connect(..., timeout=秒)`，Rust `ConnectOptions` 和 `Runtime::connect_with_options` 提供同一能力。省略或 None 不增加调用方总期限，保留已有阶段保护；有限非负秒数为本次操作预算，0 立即到期，负值/NaN/infinity 拒绝。Python 只传配置，不新增等待线程。Core 在操作入口计算一个绝对 deadline，池等待/连接/握手/live acquire/Relay resolve、probe、重试都使用剩余预算，不能每阶段重置。

到期返回原有 `CallDeadlineExceeded`，details 标记 `operation=connect` 和 `transport_phase=pre_dispatch`，注明失败阶段。尚无 CRM 业务调用，不执行资源、不进行业务重放。超时解除本次 pending 和连接引用；已损坏或写出部分控制帧的流隔离，健康共享连接不因一个等待者超时而关闭，晚响应按 native owner 收尾。阻塞外层不以“返回后仍无限占有后台线程”伪装期限完成。

T9 在 T2 的权威获取改动整合后实施，并补充原生/SDK真实测试。Windows 使用无响应 Named Pipe 对照；Unix 可在隔离自有子进程暂停服务。复现结果保存在 `/tmp/c2-074-connect-probe-result.json` 与日志中；首个探针配置参数错误不计为 runtime 证据，最终记录保留准确结果及哈希。

## T1 详细要求：自定义 Unix 端点根目录

默认目录使用 `0700`。应用提供的最终目录允许 `0755` 等模式：目录归属当前运行用户，当前用户具备所需的读、写、遍历权限，其他用户不能修改目录内容。应用负责创建该目录，C-Two 管理其中自己的端点文件。

0.7.3 要求最终目录恰好为 `0700`，并在 socket 开始监听之后才设置 `0600`。放宽目录限制必须同时调整这个顺序，避免宽松 `umask` 下出现可连接的权限窗口。依据：[目录检查](../../core/transport/c2-local/src/unix_common.rs)、[监听器初始化](../../core/transport/c2-local/src/unix_managed.rs)。
