# Contract Release Deferred Capabilities

**Date:** 2026-07-24
**Status:** Open
**Scope:** Capabilities intentionally not provided by the route-independent `ContractRelease` and active portable-payload composition slices

## Implemented Baseline

C-Two can validate and canonicalize the currently released v1 descriptor, construct an immutable content-addressed `ContractRelease`, serialize a strict `c-two.contract-release-ref.v1`, verify that reference against resolved descriptor bytes, and derive an `ExpectedRouteContract` only after a route name is supplied. The active 2026-07-24 implementation replaces the descriptor with `c-two.contract.v2`, delegates nested payload values to the frozen FastDB portable-payload Core, and keeps the reference schema unchanged because its shape and route-independent meaning do not change.

## Guardrail

Do not add a JSON/pickle portable transport, a C-Two-owned FastDB parser, an unsigned `trusted` flag, a compatibility alias for call-db, an unsafe existing-tree merge, or a placeholder SDK to make these rows appear complete.
