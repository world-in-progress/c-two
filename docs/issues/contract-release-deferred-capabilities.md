# Contract Release Deferred Capabilities

**Date:** 2026-07-24
**Status:** Open
**Scope:** Capabilities intentionally not provided by the route-independent `ContractRelease` and active portable-payload composition slices

## Implemented Baseline

Rust `c2-contract` now validates and canonicalizes `c-two.contract.v2`, derives and verifies its ABI/signature fingerprints, extracts ordered nested FastDB JSON values without interpreting them, constructs an immutable content-addressed `ContractRelease`, serializes a strict `c-two.contract-release-ref.v1`, verifies that reference against resolved descriptor bytes, and derives an `ExpectedRouteContract` only after a route name is supplied. The reference schema remains unchanged because its shape and route-independent meaning did not change.

Rust `c2-codegen` now delegates every opaque nested value to the official FastDB Rust projection, preserves structured Core errors, verifies Core identity and artifact hashes, deduplicates codegen by Core digest, and composes deterministic Rust/Python/TypeScript payload subtrees with C-Two-owned release metadata and target modules. Its generic composer rejects nonportable, case-colliding, duplicate, and file/directory-conflicting paths, bounds inventory/bytes, and atomically publishes a complete new regular-file tree to an absent destination. `c3` publishes that same set for all three targets; the Python native extension projects it in memory with structured errors; generated Rust compiles, generated Python imports against a locally built wheel from the audited FastDB source, and generated TypeScript type-checks while retaining C-Two's HTTP/relay/IPC/SHM transport surface.

The Python runtime now exposes only an explicit `@cc.transfer(input=..., output=...)` portable boundary whose value is `fastdb4py.payload.Payload`. FastDB Core compiles the nested value and owns its canonical identity, digest guard, binary open, views, materialization, and invalidation. C-Two transports opaque binary bytes, opens copy-backed receive owners, invalidates held outputs before releasing their response lease, invalidates borrowed resource inputs before releasing the request lease, and preserves FastDB code, symbol, path, message, and details in C-Two errors. The old call-db inference, sidecar, bridge, public exports, tests, examples, and active benchmark variants are removed. The Rust CLI also removes the stale `contract artifacts` subcommand and `contract infer --artifacts` flag rather than forwarding to Python entry points that no longer exist.

The recorded runtime proof now generates deterministic Rust and Python contract artifacts through the shared authority path, compiles real Rust client/host harnesses against the public `c-two` Rust SDK and official FastDB Rust crates, and imports the generated Python client against official `fastdb4py.payload`. The frozen matrix executes exactly 18 passing rows: no payload, record, and object graph across Rust client → Rust host, Rust client → Python host, and Python client → Rust host over direct IPC and explicit relay. Every relay row starts a real standalone `c3`, performs contract-scoped resolution plus token-scoped upstream readiness, records the observed route token, and makes one non-replayed business call. The strict development receipt rejects missing, duplicate, reordered, skipped, xfailed, non-passing, nonportable, or unknown evidence.

The generated Node proof executes another exact 12-row matrix: no payload, record, and object graph over direct IPC, explicit relay, relay-aware verified local IPC, and relay-aware HTTP. The suite installs locally packed `fastdb4ts` and `@c-two/c2-mem-ffi`, generates every contract tree through the real `c3` command, and calls real Rust and Python hosts. Route-token-bound probes and calls, public FastDB payload construction, checked-view invalidation, materialization survival, idempotent release, the frozen digest cause, opaque allocator rejection/release, same-path fallback denial, pre-dispatch-only HTTP retry, and dispatch-uncertain non-replay are covered. Its strict development receipt records only the audited Node platform and keeps browser runtime explicitly unverified.

The proof covers `str`, `wstr`, bytes, nested lists, null/empty values, shared references, nullable references, self/mutual cycles, materialization, route mismatch, FastDB digest mismatch, route disappearance, held-output invalidation, borrowed-input invalidation, owned-response release, and Rust checked-view invalidation. Rust and Python project the same immutable connect-time route UID/revision through Core, and direct IPC now projects contract mismatch through the canonical public `ContractMismatch` error rather than leaking a native runtime exception. The Rust host deliberately uses a copy-backed `RequestLease::into_owned_bytes` path; its SHM and reassembly-handle copies are bounds-checked by `c2-mem` before transport storage is released.

The completed local release candidate adds bounded `ContractLimits`, establishes language-neutral `c2-core` as the single owner of route selection, retry, host registration, client calls, error normalization, and transport lifetime ordering, and exposes the supported Rust user package as `c-two` / `c_two`. Python projects that same Core facade through PyO3 instead of owning an independent IPC/HTTP/relay orchestration layer. Python-only pickle/thread-local invocation remains explicitly nonportable.

FastDB implementation commit `7eb74734926bd8fe911229eee9744a6dd8172487` and C-Two implementation commit `bf6f5c950959bcd2723cf3c7bfe772c9ee91dc02` produce one canonical 42-artifact candidate. Version-only Rust, no-index CPython 3.10/current, and tarball-only Node consumers pass outside source/sibling checkouts; candidate-bound receipts pass 18/18 Rust/Python rows and 12/12 generated TypeScript Node rows. The [closure report](../reports/2026-07-24-rust-sdk-portable-payload-local-release-candidate.md) retains exact hashes and claim limits. These bytes are not official packages or hosted evidence.

## Guardrail

Do not add a JSON/pickle portable transport, a C-Two-owned FastDB parser, an unsigned `trusted` flag, a compatibility alias for call-db, an unsafe existing-tree merge, or a placeholder SDK to make these rows appear complete.
