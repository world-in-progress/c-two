# C-Two 0.7.3：可直接指定的端点目录与长路径

状态：实施与验证。代码基线为 `7590977489d1cf920df0f0b676ec02ce6eb3cba5`。本文确定 0.7.3 的实现范围和验收条件；设计证据保留原始范围，实施验证另行记录。

## 1. 目标形态

用户配置的目录就是实际存放端点的目录。C-Two 不追加用户目录、版本目录或 `.sock` 后缀。默认配置选择 `/tmp/c2-<uidhex>`，显式配置直接覆盖这个最终目录。

```text
默认：   /tmp/c2-<uidhex>/<32 字符端点标识>
自定义： <配置的最终目录>/<32 字符端点标识>
```

目录长度不再被 Unix socket 的 `sun_path` 容量挤占。Linux/macOS 的 bind、connect 和存活探测都通过已打开的目录句柄定位短文件名，用户可以使用文件系统能够实际打开的目录路径。C-Two 不新增 21、70 或 76 字节这样的目录上限。正式验收至少覆盖 512 字节 UTF-8 目录；512 是验收下界，不是产品上限。

本次直接替换旧布局，删除对应旧派生逻辑、测试假设和文档描述。不新增内部版本号、版本目录、兼容开关或旧布局共存机制。既有线格式编号不因路径调整而升级。

## 2. 配置与命名

现有入口保持一套：Python `cc.set_local_endpoint(root=...)`、Rust `LocalEndpointOptions.unix_root`、环境变量 `C2_IPC_ROOT` 和 c3 `--ipc-root`。`root` 的含义统一为最终端点目录。优先级继续由 Rust resolver 处理：显式代码/CLI > 进程环境 > `.env` > 默认值。

```python
from pathlib import Path
import c_two as cc

ipc_dir = Path('/Users/soku/Library/Application Support/my-app/run/ipc')
ipc_dir.mkdir(parents=True, exist_ok=True, mode=0o700)
cc.set_local_endpoint(root=str(ipc_dir))
# 实际 socket 位于 ipc_dir / <32 字符标识>。
```

默认位置可由 C-Two 初始化为私有目录。自定义位置由应用预建；C-Two 打开并验证该目录，只管理其中自己的端点、租约及现有协调文件。不会递归创建应用的父目录、修改已有目录权限或在回收时删除目录。显式指定与默认值相同的最终目录，得到相同的端点身份和默认目录初始化行为，不另设配置来源分支。

路径保留合法的 Unicode 和空格，长度按 UTF-8 字节计算。继续拒绝相对路径、NUL 和 `..`；重复分隔符及末尾分隔符沿用现有规范化。纯配置查询不访问文件系统；目录存在性及权限检查在实际 I/O 边界执行。

端点标识取现有逻辑 server id 的 SHA-256 前 16 字节，输出 32 个小写十六进制字符。保留确定性寻址，不增加发现服务、映射表、随机重命名或依赖。小写编码适用于大小写不敏感文件系统。完整逻辑地址和实例身份仍由现有租约记录、握手校验承载。

同一标识的 socket 使用无后缀的短文件名，对应租约仍可使用 `<标识>.lease`；租约文件名不进入 `sockaddr_un`。协调文件沿用现有机制。维护枚举只识别当前名称形态及当前作用域内的目标。

`LocalEndpointContext` 保存最终目录；移除 `UNIX_NAMESPACE_LAYOUT`、路径布局字段以及 SDK 中对应的 `layout` 投影。namespace id 使用 backend、最终目录与现有 OS scope，去掉布局版本输入。路径派生仍只有 `c2-config` 一个实现。

## 3. 用户目录为什么能够变长

基线把 `/c2-<uid>/v2.2/<64 位哈希>.sock` 追加到用户 root。UID 501 时追加 82 字节，macOS 的绝对 socket 地址检查给 root 留下 21 字节。仅改成无后缀 32 字符文件名，也只能把普通绝对寻址的目录预算提高到 70 字节；深层应用目录仍可能超限。

基线 [unix_common.rs](../../core/transport/c2-local/src/unix_common.rs) 已有目录句柄相对 bind：Linux 使用 `/proc/self/fd/<fd>/<name>`，macOS 在独占的短时线程中调用 `pthread_fchdir_np` 后绑定短文件名。需要补齐的是 [unix.rs](../../core/transport/c2-local/src/unix.rs) 的连接入口，以及 [unix_managed.rs](../../core/transport/c2-local/src/unix_managed.rs) 中 macOS 存活探测的绝对路径回退。

| 平台 | 内核 socket 操作使用的名称 | 用户目录的实际约束 |
| --- | --- | --- |
| Linux | `/proc/self/fd/<已持有的目录 fd>/<短标识>` | 文件系统路径、权限及目录打开能力；沿用现有 `/proc/self/fd` 依赖 |
| macOS | 独占短时线程中的相对短标识 | 文件系统路径、权限及目录打开能力 |
| Windows | 现有登录 SID 范围内的 Named Pipe 名称，使用同一短标识 | Named Pipe 的命名约束；Unix 目录配置仍报告不适用 |

`LocalEndpoint.os_name()` 仍返回用于显示和定位文件的完整路径，但这个字符串不再直接交给 Unix `connect` 或 probe。完整路径可以长于 `sockaddr_un.sun_path`。`c2-config` 删除完整路径的 socket 地址容量检查；`c2-local` 检查真正传给内核的短名称。操作系统拒绝目录路径时返回实际路径/I/O 错误，不改写用户目录，也不静默切回 `/tmp`。

### macOS 连接与探测

复用现有目录 fd 和独占线程方式，补充一次非阻塞 `connect` 的启动操作。线程持有自己的目录描述符和 socket 所有权，只执行目录切换及一次原生连接调用，不等待网络完成。连接若进入 pending，由调用方的异步 I/O 驱动观察可写和 `SO_ERROR`；失败或取消关闭该次连接的 fd。线程交接失败也必须释放 fd。

这发生在建立物理连接时，不发生在每次 RPC 上。不得使用进程级 `chdir`，也不得在共享线程池上遗留线程私有 cwd。存活探测复用同样的目录定位方式，执行现有非阻塞、仅能否决回收的探测语义。绑定、连接、探测使用同一个目录和短名称，避免出现“能绑定、客户端连不上”或“能通信、端点无法回收”的半完成状态。

### Node 连接投影

Node 的默认 Unix 连接也消费同一原生连接能力，不把完整路径交回 `node:net.createConnection`。FFI 提供有界的已连接描述符交接，在 N-API worker 中执行原生连接；异步工作保留捕获上下文，完成后用拥有描述符的对象移交给 Node Socket。关闭、交接失败与未消费结果各自释放原生所有权。Windows 保持 Named Pipe 连接入口。该补齐不改变 IPC wire、凭据 schema 或 ABI 版本。

### 目录与资源所有权

[ManagedNamespace](../../core/transport/c2-local/src/unix_managed.rs) 改为打开一个最终目录，去掉“私有父目录＋版本子目录”的结构假设。保留当前目录权限验证、目录描述符、协调器、监听租约、实例身份及精确文件回收。父目录不需要符合私有 namespace 的 `0700` 条件，例如默认位置的父目录 `/tmp`。

这些文件操作继续围绕已验证的最终目录进行。目录改名或替换后的行为由现有目录身份检查处理。应用提供的目录及无关文件不属于端点清理目标。

## 4. 各入口同步到同一个目录语义

Core Runtime 的首次本地 I/O 冻结点继续冻结完整 endpoint context。Python、Rust、FFI、TypeScript、c3、管理探针以及 Relay 上游都消费这一个最终目录；SDK 不另行拼接路径。

凭据记录最终目录及对应 namespace id，默认和自定义 Unix 目录使用当前已有的带目录凭据形态。删除依赖旧默认 `/tmp` 和旧目录布局的隐式重建特例，不添加新的 schema 编号或旧 Unix 布局读取分支。Windows 使用既有内核端点凭据。

凭据容量必须覆盖长目录，避免创建端点成功后无法 inspect/reap。现有 JSON 读取上限由 4 KiB 调整为 32 KiB：覆盖 Linux 绝对路径打开边界内的目录、现有 1024 字节逻辑地址及 JSON 转义开销；编码和解码采用同一有限上限。FFI、CLI 和语言绑定使用同一原生上限，不增加一套路径长度策略。

Relay 的 namespace 比较改为基于最终目录；相同目录、相同逻辑地址得到相同端点。仍运行真实身份握手和路由契约校验。Windows 的目录不适用行为、Named Pipe 生命周期与实际登录权限进入同一轮验证。

## 5. 实施范围与验收

实施集中为三步，不新增子系统：

1. `c2-config`：最终目录语义、32 字符标识、删除版本路径层与完整 socket 路径检查；同步 resolver 和 namespace id。
2. `c2-local`：扁平目录访问，bind/connect/probe 的目录相对寻址，凭据和维护名称规则；先用真实本地 I/O 覆盖长路径。
3. 同步 Core、SDK、FFI、c3、Relay 的投影和测试，更新配置指南、生命周期指南及 0.7.3 说明。版本号按项目发布流程处理，不给内部机制新增版本。

验收按变更影响面集中执行：

| 检查 | 必须证明的行为 |
| --- | --- |
| 配置 | 代码、环境、`.env`、CLI 得到同一最终目录；无额外 uid/版本子目录；默认目录身份稳定；冻结语义有效 |
| 实际路径 | 名称为 32 字符小写十六进制；socket 无 `.sock` 后缀；namespace 与租约使用同一派生结果 |
| 长目录 | Linux/macOS 上真实运行 128、256、512 字节目录，包含空格和中文；实际 socket 绝对路径超过 108 字节仍可往返通信；平台允许时继续覆盖 768 字节 |
| 连接所有权 | 非阻塞即时成功、pending、连接失败、调用方取消；目录 fd 和 socket 正确关闭，进程及调用线程 cwd 不受影响 |
| 生命周期 | 长目录下 inspect、kill＋OS wait＋精确 reap、sweep 完整走通；目录及无关文件保留；正常关闭和再次绑定成功 |
| 凭据 | 长目录与长逻辑地址可编码、解码及维护；转义开销和 32 KiB 边界受到实际测试；默认与自定义没有两套路径重建 |
| SDK/CLI/Relay | Python/Rust 真实 IPC；FFI/TypeScript 端点上下文及维护；c3 使用相同目录；Relay 的 IPC 与 HTTP 路由验证 |
| Windows | 2022/2025 x64 实际 Named Pipe 连接、生命周期和普通/非管理员消费；明确拒绝 Unix 目录参数；短名称派生一致 |

更新旧测试中被替换的路径字面量和目录结构断言，保留实际权限、目录替换、精确回收、取消、资源释放及完整路由契约覆盖。完整 SDK、现有跨语言矩阵和发布门禁在组合实现完成后执行，不为这份设计重复运行。

## 6. 已取得的设计证据

2026-10-09 在 macOS 26.6.2 ARM64 进行了独立系统调用试验。目录含中文和空格，分别长 128、256、512、768 个 UTF-8 字节；32 字符 socket 名使完整路径分别长 161、289、545、801 字节。四组均完成目录相对 bind、非阻塞 connect、数据往返、活体及死亡探测、socket 删除和临时目录清理，进程 cwd 未改变。

[试验结果](../reports/evidence/0.7.3-endpoint-path-feasibility.json) 证明 macOS 原语能够支持该方向。试验中 connect 均即时成功，尚不覆盖 Rust/Tokio 的 pending/cancellation 接入；也未运行 Linux、Windows 或 C-Two 的完整调用/维护链。上述项目是实施验收条件，不能把本试验记作 0.7.3 已实现或全平台通过。
