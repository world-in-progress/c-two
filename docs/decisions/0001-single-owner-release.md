# 单一属主释放

状态：已采用（2026-11-01）。

每个共享内存池只由属主进程写。对端只读映射，用完一块后经原连接发释放记录；属主收到记录，或确认对端结束（读到 EOF，或 Unix 本地流读到 ECONNRESET）之后，才回收这块。Core 在复制完成后立即释放传输租约，请求与响应两个方向都是；SDK 的 hold 只保留本地副本。这样，"别的进程持着分配器锁时被挂起或死掉"这类失效从根上消失：R07 的保留与重试、跨进程锁字、死亡观察、dedicated 段的 `read_done` 一并删除；hold 与慢方法也不再占用对端的池。

不按等待时长回收：共享映射无法撤销，到点复用会让恢复过来的对端读到别人的数据；调研里只有 iceoryx 一代这样做，它自己的代码判为不安全。因此同时删除自动心跳，它超时后只能停用连接，什么也收不回来。

这一批不加按连接的借出额度：复制后释放已把占用限在在途数据，池用满时由现有的分配回退兜住正确性；按流与按连接的两级窗口留给流式 RPC。

考虑过而没有采用：对端继续直接释放（R07 那类失败无法根除）；每连接一个响应池（段与映射随连接数成倍增长）；按心跳回收（不安全）；共享内存归还环（更快，但多一块可写共享区和等待设计，只在基准证明释放通道是瓶颈时再议）。
