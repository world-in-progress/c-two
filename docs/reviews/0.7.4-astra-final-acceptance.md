保留的历史与限制

e6 初审仍是当时的 Request changes，原报告 SHA-256 `e6766950de200bb2b0afc196f1bec05f857c3a673eb1e4cbf50517f13f136b85` 未改变。F1/F2/F3 在 `aa96f151`/`4e9a238e` 修复，不能重写 e6 为通过。e6 Windows 2025 原 H1 fixture 失败、8c 的 Windows run 37989052554 eager 真失败以及它对应的旧 Unix 成功都保留各自归属。仅本次 `0deda445` 的新证据关闭后续平台门禁。T1 首次 transient AddrInUse 也未被删除；duplicate-lock 机制已确定修复，但原日志缺具体 fault/继承轨迹，仍不能唯一归因该单次事件。

T9 每条成功认领的 retired 记录可以使用临时 native cleanup worker；单记录 CAS 去重和有限尝试有证明，全局跨记录线程总量没有固定上限，本轮没有高失败吞吐基准。HTTP 拒绝 body 收尾限于无 Expect、已声明且允许的 known length，并受单次 2 秒预算限制；超慢、坏 framing、unknown 或取消时不保证对端必定收到完整 canonical response，但没有伪造已收到的错误或再次准入。它不表示 HTTP 缓冲零分配，也不是全 HTTP 连接数的新增上限。ForwardingDomain drain 观察 native business work，不等于所有 HTTP/OS 缓冲或 held backing 同时为零。
