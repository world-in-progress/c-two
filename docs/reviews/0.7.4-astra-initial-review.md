### F1 [P1] macOS ACL 可以使“其他用户可修改”的自定义目录通过检查

位置：`core/transport/c2-local/src/unix_common.rs:134-163`、`:297-308`，尤其 `verify_directory_stat` 的 `mode & 0o022` 检查，以及 `validate` 中针对当前有效身份的 `faccessat`。

触发：当前用户持有的 `0755` 目录，带 `group:everyone allow add_file,add_subdirectory,delete_child` 扩展 ACL。本机 macOS UID 501 上，精确源码的 `LocalListener::bind` 接受该目录；模式位仍为 0755。日志包含真实 ACL 和 `ACL_OTHER_WRITABLE_ROOT_ACCEPTED=true`。`faccessat` 确认当前用户的读、写、遍历能力，无法证明其他身份没有 ACL 写权限。

影响：违反 T1 的“其他用户不能修改目录内容”要求。允许其他身份添加、删除或替换端点、租约、协调对象，破坏以目录受当前用户控制为前提的身份检查与清理安全性。现有 root/nobody 测试只覆盖普通 0755/0600 组合，没有覆盖扩展 ACL。本轮没有以普通 UID 冒称执行了跨用户进程测试。

所需修复：对已固定的目录描述符检查扩展 ACL，拒绝能授予其他身份目录内容修改权的目录，或者对无法可靠判定的 ACL 保守拒绝并提供明确诊断；不要 chmod 应用目录或引入布局版本。维持正常 0755、无写授权的安全 ACL、默认 0700 和 Windows SID 行为。增加 macOS 实际 ACL 的正、负用例，并在支持的 hosted 身份环境验证实际外部写入被拒绝。

证据：`/tmp/c2-074-astra-probe/src/bin/acl.rs`，`/tmp/c2-074-astra-acl-probe-locked.log`。探针删除了自有端点和目录。

### F2 [P1] 首连超时将预热 SHM 永久留在 retired 记录中，恢复后的连接仍因预算不足失败

位置：`core/transport/c2-ipc/src/pool.rs:243-246`、`:300-319`、`:545-555`、`:676-697`、`:925-929`、`:1351-1362`。`FreshClientGuard::retire` 使用已经耗尽的调用期限关闭；未确认记录成为 `UnconfirmedIdle`。正常 acquire 只清理 `Confirmed`，`UnconfirmedIdle` 的重试集中在显式 `close_all`。`core/transport/c2-ipc/src/client.rs:5035-5058` 在零剩余期限下不能完成池分离。

真实复现：1 MiB segment、`pool_prewarm_segments=1`、SHM budget 1,536,000 bytes；连接一个接收握手但暂不回应的真实 LocalListener，调用期限 100 ms。首连正确返回 canonical `CallDeadlineExceeded` / `handshake`。等待 300 ms 后，预算仍占用 1,052,672 bytes；使服务回应后，下一次 acquire 在连接前即因该残留预算失败。显式 `close_all` 后占用变为 0，再次 acquire 成功。没有资源业务调用参与。

影响：支持的预热配置在一次暂时停顿后就可能无法正常恢复，必须关闭整个连接池/会话。更大预算仅推迟多次失败后的耗尽。默认 lazy-pool 的 SIGSTOP 恢复用例通过不能覆盖该问题。保留 cleanup owner 的做法有必要，但记录不能在 native 工作已终止后无限期占有 backing。

所需修复：为取消的 fresh client 安排可最终完成的原生清理或有期限的后续重试，保留精确 client 所有权、未确认关闭记录、预算记账和生命周期屏障；不能提前释放仍使用中的 payload/backing，也不能在调用期限后阻塞当前调用方。以该真实 prewarm 反例补回归，证明服务恢复后不依赖全池关闭即可重新连接，并检查反复超时不会累计不可回收的 SHM/retired 记录。

证据：`/tmp/c2-074-astra-probe/src/main.rs`，`/tmp/c2-074-astra-prewarm-probe-locked.log`。复现采用 Core lockfile 中相同的依赖版本，额外 package 仅为探针自身。所有 peer 任务、线程和自有端点完成清理。

### F3 [P2] 失败绑定在 Lease guard 建立前退出，存活的重复描述符继续持有监听租约

位置：`core/transport/c2-local/src/unix_managed.rs:1143-1177`、`:1233`。既有 `Lease::release` 在 `:970-981` 明确执行 `LOCK_UN`，但 `bind_managed_at` 只在成功返回时把原始 File 包装为 Lease；前面的 chmod/listen/record 等失败路径只 drop File。

确定性复现：在 `/tmp` 的固定源码副本中，唯一改变生产执行路径的测试注入，是在已有 `SocketPermissions` 失败点保留 `guard.ownership.try_clone()`。原绑定正确失败且 socket 已清理；只要该重复描述符仍存活，立即重绑必定得到 `managed IPC endpoint already has an active or unverifiable listener`；关闭重复描述符后立即成功。测试 1 项，0.02 秒。该注入模拟同一 open file description 的 fork/dup 引用，没有更改租约或回收算法。

影响：多线程进程在失败 bind 附近 fork/继承描述符时，已失败的监听尝试可能继续占有逻辑端点。成功 listener 已通过 Lease 的显式 unlock 防止同类问题，错误路径遗漏该保障。这是既有错误路径缺口，在 T1 新增失败点和重绑验收中暴露，不能简单归为本次新引入的全部行为。

所需修复：成功取得 lease flock 后立即建立 Lease RAII owner，使每个错误返回都显式解锁同一个 open file description，并保留具体错误、身份匹配撤销及原 gate pin 顺序。增加存活 duplicate 的失败后重绑回归。测试用 `dup2` 破坏 socket descriptor 时还应保持原 close-on-exec 条件，避免注入自身扩展继承窗口。

与原 transient 的关系：`/tmp/c2-074-t1-host-r2.log:236-245` 的首次失败真实存在，后续 10 次通过不能否定。本复现给出了同一报错的确定性机制；原日志未记录当时的 fault 变体或描述符，因此不能声称已经证明原事件完全由它导致。修复后应保留旧日志和该归因边界。

证据：`/tmp/c2-074-astra-rebind-probe-locked.log`，`/tmp/c2-074-astra-rebind-instrumentation.patch`，`/tmp/c2-074-astra-local-copy/`。首次错误的 exact filter 选到 0 项不计作验证；修正全限定测试名后的 1 项才是上述证据。

## 规模、可读性和性能判断

T5/T6 有实际维护收益：T6 删除退役 codec、导出和测试专用 panic helper；T5 删除空参数和重复投影，保留真实行为差异。其它较大的 descriptor、SHM 发送合并、执行器合并、Node/Core 投影、strip/依赖裁剪没有在证据不足时混入。

T9 的 caller deadline 与 cancellation-safe exact lease 确有需求，不能靠在 Python 外侧加 waiting thread 或只包一个外层 timeout 替代。按层保留 typed error 的 deadline helpers、已存在异步运行时的有期限初始化 gate，以及 exact-entry 引用释放有明确用途。相应增加的 retired 状态管理需要 F2 的最终收尾机制才能证明成立。当前版本没有性能测量支持整体更快或内存更小的结论；live acquire 增加控制往返是正确性成本，业务调用仍不重放。未发现要求在本次继续扩大重构范围的依据。
