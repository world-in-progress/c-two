# C/FFI ABI

This page defines the current `c2-mem-ffi` ABI boundary. Its consumer is the Node client of the TypeScript binding.

## ABI 10 and consumers

The current `c2-mem-ffi` ABI is 10. A consumer reads `c2_mem_ffi_abi_version` before loading any other symbol and rejects every other version. Rust Core owns endpoint acquisition, IPC and relay transports, business records, loans and their release. The Node binding passes contract identities and request bytes to Core and receives local response buffers. [IPC 18 handshake](ipc-handshake.md), [memory policy](memory-policy.md)

## Endpoint context

`c2_mem_ffi_local_endpoint_context_capture` captures c2-config's endpoint configuration once. A NULL root inherits the process environment, `.env` and the platform default; a non-NULL UTF-8 root is an explicit override and reads neither. Windows uses the current TokenUser SID and rejects every root override. The `name` and `namespace_id` length/copy pairs answer from the captured context, unaffected by later environment changes; a copy needs the reported length plus one byte. `c2_mem_ffi_local_endpoint_context_free` frees the context once.

## Client domain, endpoints and calls

- `c2_mem_ffi_client_domain_new` creates a Core Runtime for a client-only domain, using the captured context or native endpoint configuration when the context is NULL. Its `options_json` parameter must be a UTF-8 JSON object (`"{}"` when passing no overrides; unknown keys are rejected). Optional keys `memoryBudgetBytes`, `fileSpillBudgetBytes` and `maxOutstandingCalls` set client role capacity and accept non-negative `u64` JSON numbers or decimal strings. Omitted keys inherit the native defaults and environment. One domain covers all the connector's endpoints, physical connections and reconnects. Freeing the domain releases its own reference; live endpoints, calls and buffers keep their owners.
- `c2_mem_ffi_client_domain_stats` returns a read-only client-role JSON snapshot. It projects the client domain's identity, generation, frozen and closed state, its memory and file-spill byte cells and its call-slot counters. An inactive role has null counters. Neither this function nor Node `connector.stats()` reads the environment, creates a role domain or freezes its options. [Role statistics](memory-policy.md#statistics-and-payload-lifetime)
- `c2_mem_ffi_endpoint_context_new` performs no I/O. Endpoint addresses are `ipc://`, `http://` or `https://`. Its UTF-8 JSON options object accepts `connectTimeoutMs` and two transport-specific keys. IPC accepts `expectedServerIdentity`, checked on every acquisition. HTTP(S) accepts `mode` with values `relay_aware` (the default) and `explicit_relay`. Each relay-aware endpoint has its own anchor URL and uses verified local IPC when eligible, with HTTP for remote acquisition. Explicit relay endpoints use HTTP. All endpoints created by one domain share its budgets. Unknown option keys and invalid option values are rejected.
- `c2_mem_ffi_endpoint_context_prepare` validates the complete route contract and retains a route-bound Core client. Its nullable millisecond timeout and explicit `connectTimeoutMs` cap preparation at the smaller of the two budgets. Zero expires immediately. A direct IPC preparation returns `{serverId, serverInstanceId, connectionId}` with a decimal connection ID. A relay endpoint also returns `path` and uses JSON null for the three IPC fields when Core reaches the route over HTTP. `c2_mem_ffi_endpoint_context_connection_snapshot` observes the physical IPC connection from the route's last successful preparation and returns the same identity fields and nullable `endReason`. Its `json` pointer is NULL when there is no observed IPC connection. Deactivation stops new operations. Endpoint close completes asynchronously.
- `c2_mem_ffi_call_begin` starts a unary or server-stream call before its input is encoded. A NULL timeout is unlimited; a value sets one absolute deadline for encoding, admission and the whole iteration. `c2_mem_ffi_call_charge_input` reserves the input in the domain's budget before `c2_mem_ffi_call_dispatch` copies the borrowed bytes. A successful dispatch returns JSON with the target that the original call record selected when it handed its input to the transport, `{path, serverId, serverInstanceId, connectionId}` with the connection ID as decimal text and nullable IPC identity fields on HTTP; a failed call keeps its typed error. `c2_mem_ffi_call_next` delivers the next response or item, and only one may be pending. `c2_mem_ffi_call_cancel` and `c2_mem_ffi_call_free` submit stream cancellation without waiting; freeing a dispatched unary call never cancels it. `c2_mem_ffi_call_observe` submits cancellation and then observes the original call record: NULL waits without limit and zero observes once. Its JSON is `{completed, error, completeItems}`, with the count as a decimal string; while the call is unfinished, `error` and `completeItems` are null. The observation timeout bounds only the wait. `c2_mem_ffi_call_check_deadline` returns `CallDeadlineExceeded`, with the call's phase, once its deadline has passed; a consumer calls it around its own encoding and decoding, which the native side cannot observe.
- An asynchronous entry takes a completion callback that owns its `C2MemFfiResult`. Normally it runs on a Rust executor thread; if executor initialization fails, it is invoked synchronously on the calling thread with the error result before the entry returns `OK`. The result owns any buffer, error or subscription handle. The consumer transfers a handle by setting its member to NULL before `c2_mem_ffi_result_free`. JSON stays borrowed until the result is freed.
- `c2_mem_ffi_buffer_data` exposes a response's local bytes. Its transport lease ended before the buffer existed ([payload lifetimes](payload-lifetime.md)). `c2_mem_ffi_buffer_release` frees the buffer after the consumer has detached every external view of it.
- `c2_mem_ffi_error_parts` returns structured error JSON: `message`, `code`, `canonicalName`, `details`, `transportPhase` (`pre_dispatch` or `dispatch_uncertain`), `category`, the protocol versions of a version mismatch and the local I/O cause. Outer Core transport phases take precedence over inner semantic details; call-scoped `LifecycleError` failures project the call's scope phase while resource semantic errors carry no phase. A consumer reads the phase from this JSON, never from a display string. `c2_mem_ffi_error_free` frees the error.


## Keyed unary calls and outcomes

- `c2_mem_ffi_call_begin` takes `const uint8_t *call_id`, `size_t call_id_len` and `const char *metadata_json` after the timeout pointer. Pass `NULL, 0` for an unkeyed call; otherwise pass 1–128 ASCII bytes from `[A-Za-z0-9_-]`, with the length excluding any terminator. Pass `NULL` for empty call metadata; otherwise pass a UTF-8 JSON object mapping `CallMetadata` string keys to string values (duplicate JSON keys, non-string values and keys or values violating `CallMetadata` bounds are rejected). The function validates and copies the call ID and metadata before returning. Passing a call ID with `server_stream` set fails at this boundary before creating a call.
- `c2_mem_ffi_recover_call` takes an endpoint with a prepared route, the route and unary method names, the call ID pointer and length, the nullable millisecond timeout, nullable `const char *metadata_json`, and the completion callback and user pointer. It validates and copies metadata before returning and sends no input payload. The callback receives a result owning the local response buffer or a structured error, including 723 on a miss or 724 on admission denial. The timeout bounds the caller's wait (`NULL` is unlimited; `0` expires immediately). Endpoint close still waits for the recovery to settle.
- `c2_mem_ffi_query_call` takes the same arguments as recovery except for the method name, including nullable `metadata_json`. It completes with an error or a JSON snapshot containing `status`, `method_name`, `result_available`, `result_unavailable_reason`, `error_code` and `error_details_available`. The method, reason and numeric code use JSON null when absent. The callback owns the result and the JSON is borrowed until the result is freed. Query admission uses a control slot independent of business call slots, and its timeout covers queue waiting as well as the query round trip.

Read `callId` from structured error JSON when Core reports dispatch uncertainty for a keyed call. The outcome errors and snapshot semantics are defined in the [error reference](errors.md#call-outcome-errors) and [Python usage](python-usage.md#keyed-unary-calls-and-outcomes).

## Topic subscriptions

- `c2_mem_ffi_subscription_open` takes a prepared route, topic name, UTF-8 options object and nullable millisecond deadline covering open and delivery. Options are `start` (`latest` or `next`), `onLag` (`skip` or `error`) and optional `metadata` (a JSON object of validated `CallMetadata` string pairs; duplicate JSON keys are rejected). Omitting them selects `latest`, `skip` and empty metadata. NULL timeout allows unlimited time and zero expires immediately. Opening completes after Core receives READY and returns an owned `C2MemFfiSubscription` and JSON `{startSeq, topic}`.
- `c2_mem_ffi_subscription_next` permits one pending request per subscription. A delivery owns a local buffer and carries JSON `{seq, dropped}`. Each sequence and dropped count is an unsigned decimal string. The caller releases the buffer after detaching external views. Terminal errors are structured, including 718 with its cancellation cause and 720 with its lag details. After a terminal delivery error, subsequent reads return an empty result. `c2_mem_ffi_subscription_check_deadline` checks the subscription's original deadline around SDK decoding.
- `c2_mem_ffi_subscription_cancel` submits cancellation without blocking. `c2_mem_ffi_subscription_close` cancels and observes the same terminal record. NULL waits indefinitely and zero observes once. The wait result is `{completed, error, completeItems}`. When unfinished, both `error` and `completeItems` are null. A known item count is encoded as a decimal string. The wait budget does not cancel cleanup. `c2_mem_ffi_subscription_free` discards the owner's reference and submits cancellation without waiting. Delivered local buffers remain valid until released.
- Node exposes `startSeq`, `seq`, `dropped` and `completeItems` as `bigint`. Generated clients release the native buffer after decoding by default. A held delivery owns the decoded value and local buffer until its caller invokes `release()`. For relay topics, supply the same native connector as the transport's `connect` option. A relay-aware transport can also use its `ipc.connect` connector. [ADR 0005](../decisions/0005-publish-subscribe.md)
