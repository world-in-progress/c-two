# C/FFI ABI

This page defines the current `c2-mem-ffi` ABI boundary. Its consumer is the Node client of the TypeScript binding.

## ABI 8 and consumers

The current `c2-mem-ffi` ABI is 8. A consumer reads `c2_mem_ffi_abi_version` before loading any other symbol and rejects every other version, so an ABI 7 library is reported as a version mismatch, not as a missing symbol. ABI 8 projects the Rust client: the native library connects through c2-local, performs the IPC handshake and runs the single reader and writer of each physical connection in c2-ipc. A consumer never handles a socket, a pipe, a frame, a loan or a release record; it passes contract JSON and request bytes in and receives local response bytes. Endpoint functions take the logical address without a protocol selector. Historical manifests and receipts retain their actual source ABI.

## Endpoint context

`c2_mem_ffi_local_endpoint_context_capture` captures c2-config's endpoint configuration once. A NULL root inherits the process environment, `.env` and the platform default; a non-NULL UTF-8 root is an explicit override and reads neither. Windows uses the current TokenUser SID and rejects every root override. The `name` and `namespace_id` length/copy pairs answer from the captured context, unaffected by later environment changes; a copy needs the reported length plus one byte. `c2_mem_ffi_local_endpoint_context_free` frees the context once.

## Client domain, endpoints and calls

- `c2_mem_ffi_client_domain_new` creates a client domain from a captured context, or from native configuration when the context is NULL, and fixes the request policies of its JSON options, `requestShmThreshold` and `requestChunkSize`, for every connection it makes. The domain owns one payload buffer budget shared by all of its endpoints, physical connections and reconnects; `c2_mem_ffi_client_domain_stats` reports that budget and the domain's used operation slots as JSON. Freeing the domain releases only its own reference; live endpoints, calls and buffers keep their owners.
- `c2_mem_ffi_endpoint_context_new` performs no I/O. Its JSON options are `connectTimeoutMs` and `expectedServerIdentity`. `c2_mem_ffi_endpoint_context_prepare` takes the route, its complete contract and an optional expected route token (`{"routeUid": ...}`, NULL to omit); it connects, validates the contract and pins the server identity and route UID, so one endpoint carries calls to several routes of one server instance and checks each against its own token; its JSON result carries `serverId`, `serverInstanceId`, `routeUid` and `connectionId`. `c2_mem_ffi_endpoint_context_deactivate` stops new calls while calls already sent finish, and `c2_mem_ffi_endpoint_context_close` completes asynchronously.
- `c2_mem_ffi_call_begin` starts a unary or server-stream call before its input is encoded. A NULL timeout is unlimited; a value sets one absolute deadline for encoding, admission and the whole iteration. `c2_mem_ffi_call_charge_input` reserves the input in the domain's budget before `c2_mem_ffi_call_dispatch` copies the borrowed bytes. `c2_mem_ffi_call_next` delivers the next response or item, and only one may be pending. `c2_mem_ffi_call_cancel` and `c2_mem_ffi_call_free` submit stream cancellation without waiting; freeing a dispatched unary call never cancels it. `c2_mem_ffi_call_observe` submits cancellation and then observes the original call record: NULL waits without limit and zero observes once. Its JSON is `{completed, error, completeItems}`, with the count as a decimal string; while the call is unfinished, `error` and `completeItems` are null. The observation timeout bounds only the wait. `c2_mem_ffi_call_check_deadline` returns `CallDeadlineExceeded`, with the call's phase, once its deadline has passed; a consumer calls it around its own encoding and decoding, which the native side cannot observe.
- An asynchronous entry takes a completion callback, which runs on a Rust executor thread and owns its `C2MemFfiResult`. The consumer takes a member by setting it to NULL before `c2_mem_ffi_result_free`; JSON stays borrowed until then.
- `c2_mem_ffi_buffer_data` exposes a response's local bytes. Its transport lease ended before the buffer existed ([payload lifetimes](payload-lifetime.md)). `c2_mem_ffi_buffer_release` frees the buffer after the consumer has detached every external view of it.
- `c2_mem_ffi_error_parts` returns structured error JSON: `message`, `code`, `canonicalName`, `details`, `transportPhase` (`pre_dispatch` or `dispatch_uncertain`), `category`, the protocol versions of a version mismatch and the local I/O cause. A consumer reads the phase from this JSON, never from a display string. `c2_mem_ffi_error_free` frees the error.

ABI 8 removes ABI 7's per-connection memory context with its request, response, write and release entries, and the transfer of a verified connection to a foreign event loop. The [IPC handshake specification](ipc-handshake.md) describes protocol version 16. See the [memory policy](memory-policy.md) for loans and the payload buffer budget, and the [Windows native implementation](windows-native-implementation.md) for the verified connection path.
