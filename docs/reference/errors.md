# Error contracts and diagnostics

This page defines the public semantic and Core error families, canonical wire codec, transfer-hook classification, and local I/O diagnostics.

## Semantic error wire

Errors are modeled as `CCError` subclasses with numeric `ERROR_Code` values. Rust `core/foundation/c2-error` owns the canonical error registry and versioned `C2E1` JSON wire envelope, including code, name, message, and structured details. Python generates `ERROR_Code` from `_native.error_registry()` and delegates `CCError.serialize()` / `CCError.deserialize()` to `_native.encode_error_wire()` and `_native.decode_error_wire_parts()`. Do not reintroduce Python-side parsing of the error wire payload, and do not use or add legacy-named error codec APIs. Error classes are named by location, for example `ResourceDeserializeInput`, `ClientSerializeInput`, `ResourceExecuteFunction`, and `ClientCallResource`. Enum values live under `ERROR_AT_RESOURCE_*` and `ERROR_AT_CLIENT_*`.

Transfer hook errors are split by hook type: `deserialize()` failures remain `ERROR_AT_RESOURCE_INPUT_DESERIALIZING` or `ERROR_AT_CLIENT_OUTPUT_DESERIALIZING`, while `from_buffer()` / `fromBuffer()` failures use `ERROR_AT_RESOURCE_INPUT_FROM_BUFFER` or `ERROR_AT_CLIENT_OUTPUT_FROM_BUFFER`. Do not label zero-deserialization buffer view construction as deserialization. On any `from_buffer()` failure before a resource or user receives a retained value, release the native memoryview and buffer owner immediately so Rust lease stats do not retain stale holds.

Relay duplicate registration returns HTTP 409 with semantic `ResourceAlreadyRegistered` (703), which Python exposes as a `CCError` subclass. A duplicate within the same process is a local validation error. Failed relay preparation aborts the reserved local route; later registration failures retain their concrete rollback outcome. See [contracts and routing](contracts-and-routing.md#registration-mesh-resolution-and-peer-state) for the ownership rule.

Generated FastDB adapters retain a structured external cause in the appropriate client or resource phase error. Its detail fields are `cause_owner=fastdb`, `fastdb_code`, `fastdb_symbol`, `fastdb_path`, `fastdb_message`, and `fastdb_details_json`; values come from the official FastDB error object. Code generation failures retain the binding path and FastDB's code, symbol, path, message, and details JSON as separate `CodegenError::FastDb` fields. Consumers should branch on these fields rather than parse display text.

Route errors distinguish never found (`ResourceNotFound`, 701), temporarily unreachable (`ResourceUnavailable`, 702), a stale bound token (`RouteStale`, 704), closed (`ResourceClosed`, 707), and removed (`ResourceRemoved`, 708). `ContractMismatch`, `IdentityMismatch`, and `ProtocolViolation` are semantic refusals. A transport failure carries `PreDispatch` or `DispatchUncertain`; only the former is eligible for automatic fallback. An endpoint I/O failure alone does not withdraw a route. See [route bindings and fallback](contracts-and-routing.md#route-bindings-lookup-and-fallback). A call that the server refused before it entered the resource ends with the IPC 16 status NotExecuted and is pre-dispatch, with its canonical code and details kept: Rust `c2_ipc::IpcError::CallRejected`, Core and Python errors with `transport_phase=pre_dispatch`, a relay HTTP response whose status follows the code (404 not found, 406 call mode mismatch, 410 removed, 409 stale route, contract or identity mismatch, 503 closed, unavailable or over capacity, otherwise 502) with `dispatch_phase=pre_dispatch`, and the generated TypeScript `C2IpcCallRejectedError` with `transportPhase` `pre_dispatch` and `retrySafe` true. A call whose mode differs from its method's mode in the contract is refused this way with `UnsupportedCallMode` (716) and the details `call_mode` and `method_mode`. A resource error (status Failed, or HTTP 500 from a relay) never carries the phase of a call the resource made: the client removes `transport_phase` and `dispatch_phase` from its details, so the error of a resource that ran is not mistaken for a refusal. Pre-dispatch only makes a retry safe; C-Two does not retry or replay the call itself.

`CallCancelled` (718, Python `CallCancelled` and `ERROR_Code.ERROR_CALL_CANCELLED`) is the outcome of a server stream whose cancellation has finished: it is reported only after the stream's cleanup has run, with status NotExecuted, and so pre-dispatch, when the stream never entered the resource, and with status Failed otherwise. A real error from a running step or from the cleanup is kept instead. When Runtime shutdown, route unregistration or the shutdown of the relay forwarding it ended the stream, the message names that cause; a client that did not cancel the stream itself and receives `CallCancelled` learns that the server or the relay ended it. A relay that is shutting down refuses a new stream call before dispatch with `CallCancelled` naming relay shutdown. When an IPC client cannot reserve a stream item because it is longer than the whole payload buffer budget, the consumer receives `CallCapacityExceeded` as a dispatch-uncertain failure, since the resource already ran. Over HTTP, a stream whose upstream call the relay lost before its CALL_END ends with a FAILURE record, which the client reports as the relay's dispatch-uncertain error, `ResourceUnavailable`; a response body that breaks the [stream record rules](contracts-and-routing.md#server-streams-over-http) is reported as `ProtocolViolation`, and a body that ends before its terminal as a transport failure, both dispatch-uncertain.

## Public CoreError and local causes

Python Core errors are defined and typed by the public `c_two.error.CoreError` class, sharing `CCBaseError` with semantic `CCError` and retaining `RuntimeError` ancestry. PyO3 imports that same class; do not restore `_native.CoreError` or add a compatibility alias.

Local bind and connect diagnostics follow the original error chain and lifecycle watch. `IpcError::Connect` retains `EndpointIoError`; server bind failures retain `EndpointBindCause` through `ServerFailure.bind_cause`. Core exposes `LocalIoCause`, and Python projects `io_operation`, `io_kind`, `raw_os_error`, and the bind-only `endpoint_unverified_reason`. Preserve the original OS kind and code inside directory context while retaining outer policy refusals. Deadline, handshake, and contract errors must not gain fabricated local causes. These fields do not authorize retries, restart, or cleanup; do not add an error cache or infer the operation from transport phase.

The public `CoreError` category literal includes `protocol_version_mismatch`. Its `local_protocol_version` and `peer_protocol_version` are nonzero on that category and `None` on every other error. The [IPC handshake specification](ipc-handshake.md) gives the precise terminal behavior and error fields. The [local endpoint lifecycle reference](local-endpoint-lifecycle.md#public-structured-python-errors) lists all public structured fields and native cause projections.

Generated TypeScript clients read every native failure from the structured error of the [C ABI](c-abi.md), never from its message. A failure that carries a transport phase becomes `C2IpcTransportError`, whose `transportPhase` is `pre_dispatch` or `dispatch_uncertain` and whose `retrySafe` is true only before dispatch; a resource error without a phase becomes `C2CoreError`. Both keep the canonical code, name and details, and a protocol version mismatch keeps both versions. They do not read streams over HTTP yet: a stream method reached through relay HTTP forwarding fails before dispatch with `UnsupportedCallMode` (716).
