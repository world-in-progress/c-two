# Unreleased

Source changes after [C-Two 0.9.0 / c3 0.5.0](0.9.0.md) are not published; no wheel or executable is released in this batch. The approved boundary is [the IPC version-mismatch plan](../plans/2026-10-25-ipc-version-mismatch.md), and the normative description is [docs/ipc-handshake.md](../ipc-handshake.md).

The explicit Python Runtime retirement boundary is documented separately from Host shutdown: `Runtime.shutdown()` / `cc.shutdown()` starts one permanent Core retirement scope, and a pending result requires a later SDK shutdown to observe completion and replace the session. The caller's wait deadline does not cancel the cleanup driver; failure before handoff is a structured `shutdown_wait_timeout`, not pending. New start, registration and remote connections stay refused until the completed receipt is consumed. Low-level Rust/Native Host restart behavior and normal pooled connection reuse remain unchanged. Final connect publication uses the original connect deadline without retry. IPC 14, SHM 3 and C/FFI ABI 6 remain unchanged; R07 final Drop is separate. Candidate `f747a7c9` passed all 10 Actions jobs and 147 applicable gates, including Windows ARM64 and Python 3.14t; see the [acceptance record](../reports/2026-10-28-runtime-retirement-acceptance.md) for baseline failures, real Windows checks, performance costs and cleanup. This does not publish a release.

The Python public Runtime change and failed-start cleanup observation repair are implemented and validated; see the [acceptance record](../reports/2026-10-28-public-runtime-acceptance.md). `cc.Runtime()` directly exposes an independent Python binding owner over its own native session; module-level registration, connection, configuration, observations and shutdown continue through the default Runtime. Instance `start()` can wait for an empty Host's existing readiness/PONG, while later `register()` uses that Host. Instance code overrides do not inherit the default Runtime's overrides; environment and `.env` remain shared native resolver inputs. Instance-local name lookup does not search another Runtime's local routes, and cross-instance IPC uses an explicit address and matching Unix endpoint context. `cc.close(proxy)`, `cc.hold()` and call-option views retain their proxy owner. `cc.serve()` still owns signals only for the default Runtime; explicit instances require caller-managed shutdown, with no `Runtime.serve()` or automatic custom-directory deletion. After completed shutdown, the Python object receives a fresh native session under existing handoff rules, and old event subscriptions remain bound to the old source. Failed-start cleanup observations now refer to the concrete failed Server transaction, retaining pending state and terminal errors instead of selecting an empty or old Host result. Existing Rust host signatures stay unchanged; Core adds the read-only FailedStartShutdownReceipt and host_with_failed_start_receipt projection. Deterministic pending interleavings are verified at Core, and real Native/Bridge tests cover first-start and restart terminal error preservation. See the [Runtime plan](../plans/2026-10-27-public-independent-runtime.md), [cleanup receipt plan](../plans/2026-10-27-failed-start-cleanup-observation.md) and [preflight example](../../examples/python/independent_runtime.py). No version bump or release follows from this entry.

The implemented Unix endpoint identity change uses namespace disk format 3 and versioned default locations: `/tmp/c2-v3-<uidhex>` for sockets and, on macOS, `confstr(_CS_DARWIN_USER_DIR)/c2-ipc-coordination-v3` for gate/marker/lease records. Custom roots gain no suffix. Gate, marker and lease records share the format version; fixed magic `c2mgatv2` / `c2mgrec2` keeps its managed-v2 backend meaning. The gate remains 25 bytes, the marker becomes 33 bytes and the lease record's fixed header becomes 51 bytes. Persisted device fields and the redundant `RECORD_PROTOCOL` byte are removed. Live dev+ino checks and owner `context_digest`/domain remain unchanged. A recognizable other gate/marker version reports `unsupported-namespace-format` before adoption; the build does not read or delete old default directories. Unix credential JSON moves to schema 4 without device and rejects all schema 3 documents; Windows remains kernel-managed schema 1.

Default directories for different formats are separate, so no same-path cold switch is required. Upgrade all Python and Rust SDKs, c3 and Node consumers on one host together. Historical manual cleanup requires every old process to exit and be prevented from restarting. Explicitly sharing a custom physical root across disk formats is unsupported; if it reports `unsupported-namespace-format`, rebuild only after every user has exited, cannot restart and the whole root has been safely archived offline. Misconfigured cross-format roots retain identity checks that prevent deleting the other format's endpoint, while maintenance counts and reasons may be inaccurate.

An unverifiable Unix bind now retains its native `InvalidData` refusal and reports Python `CoreError.endpoint_unverified_reason` using the same finite strings as endpoint inspection; `io_kind` is `other` and no errno is fabricated. Actual OS errors retain their kind and errno. Exhausted coordinator-gate waiting is `WouldBlock`; a live address or listener lease remains `AddrInUse`. Rust introduces `EndpointBindCause { error, unverified_reason }`, uses it in `LocalIoCause::Bind`, and renames the readiness failure field to `ServerFailure.bind_cause`; `EndpointIoError` and Connect/sweep error shapes stay unchanged. Rust callers matching these public types must update their code.

Python adds `cc.server_credential() -> EndpointCredential | None`. It reads the current listener credential from the existing lifecycle watch without inspection, I/O, a namespace gate or a readiness wait. Ready and Stopping with a retained listener return the credential; before start, after bind failure and in terminal Stopped/Failed states it returns `None`. The old snapshot can remain visible between run cancellation and lifecycle finalization. It does not prove liveness or grant cleanup or owner authority. Windows returns a kernel-managed schema 1 credential while inspect/reap remain not applicable. This batch does not change IPC 14, SHM 3, C/FFI ABI 6, owner control 1 or business frames; published 0.9.0 still uses incompatible IPC 13. Exact implementation/test candidate `9f9d4de3` passed all 10 Actions jobs and 147 applicable source gates, including Windows ARM64, plus focused Windows developer-machine checks; see the [acceptance record](../reports/2026-10-27-unix-namespace-identity-acceptance.md). No version bump or publication was made. See the [implementation plan](../plans/2026-10-27-unix-namespace-identity-and-own-credential.md) and [lifecycle guide](../local-endpoint-lifecycle.en.md).

The RPC IPC handshake moves from 13 to 14 and now opens with a permanent fixed 25-byte version preamble (`C2IP`, directional flags `0x04`/`0x06`, nonzero `u32` version) before any variable metadata; the one-byte version fields in the request/response metadata are removed. A complete `VersionMismatch` preamble is a typed error carrying both versions; malformed or truncated records keep the existing decode/protocol classifications and never fabricate a peer version. Server admission fences un-negotiated CALL/ordinary-CTRL frames, duplicate handshakes and mid-connection role changes; identity checks still precede the preamble, and one shared connect budget covers both exchanges. SHM 3, C/FFI ABI 6, owner control 1 and business frame layouts do not change.

New error surfaces: Python `CoreError` gains `category='protocol_version_mismatch'` with `local_protocol_version` / `peer_protocol_version` (`None` on every other error; `transport_phase='pre_dispatch'`, no OS cause fields); Rust adds `IpcError::ProtocolVersionMismatch { local: u32, peer: u32 }` and Core `Error::ProtocolVersionMismatch { local: u32, peer: u32 }` (exhaustive matches must add them); generated TypeScript `C2IpcTransportError` gains nullable `localProtocolVersion` / `peerProtocolVersion` plus `category`, keeping cleanup failures on `Error.cause`. Relay-local route acquisition treats the typed mismatch as terminal — local cleanup then rethrow, no route fallback, no HTTP fallback, no retry — while an HTTP relay's own upstream IPC mismatch still projects the existing `ProtocolViolation` (502) with version details naming the relay/upstream pair, not the caller's local end.

Compatibility: pre-14 peers (including published 0.9.0 and older wheels) have no preamble, so mixing old and new ends remains a plain connection/protocol failure — an old wheel observes a generic connection failure with no typed projection. Low-level manual handshake callers must adopt the two-phase sequence; the old single-frame RPC handshake entry is removed.

Cost boundary: a successful new physical connection adds one local round trip and 48 net handshake bytes; calls on an established connection add nothing; a version rejection costs one Hello/VersionMismatch round trip. The generated TypeScript relay-aware local path still rebuilds and closes its IPC transport per call and therefore pays the added round trip on every call; its reuse strategy is unchanged here. The exact candidate `968f7d29` passed all 10 GitHub Actions jobs across Linux, macOS, Windows 2022/2025, Windows ARM64 and Python 3.14t. The [acceptance record](../reports/2026-10-26-ipc14-version-diagnostics-acceptance.md) retains baseline counterexamples, real Rust/Python/Node validation, cleanup and measured latency. New-format rejection on the measured macOS host returned in 0.744 ms P50 / 0.914 ms P95; this is not a cross-platform latency guarantee. Published 0.9.0/new-source mixed pairs were also tested in both directions on macOS and Windows x64; Linux old-wheel mixing was not separately tested.

R07a fixes explicit low-level Rust release ownership. `MemPool::release_handle` now returns `Result<FreeResult, ReleaseHandleError>`: buddy release failures are reported with the original `MemHandle`, rather than consumed or reported as success. `SyncClient::pool_alloc_and_write/fill` returns `RequestPreparationError`, retaining any block whose preparation cleanup failed; the block can only be cleaned up, never recovered for publication. `pool_free` returns `Result<(), IpcError>`. Exhaustive return-type annotations and error handling must migrate; no old signatures or aliases remain.

`RequestLease::release` and `ResponseLease::release` keep their original carrier on failure and clear it on success, preserving storage-before-reservation release. These changes retain pool identity, generations, allocation ids, budgets and release order. Core/SDK Held, consuming paths and final Drop were completed by the R07 follow-up described below. Public Python/SDK Rust signatures, IPC 14, SHM 3 and C/FFI ABI 6 are unchanged. See the [R07 scope](../plans/2026-10-26-r07-failed-release-ownership-evaluation.md) and [memory policy](../memory-policy.en.md).

R07 completes failed-release ownership. An explicit native cleanup failure keeps the original lease, budget charge and concrete connection pin with its holder: Core `HeldResponse`, Rust `Held::release()` and Python `HeldResult.release()` can be called again, and the FastDB invalidator runs at most once, including after a raised error or panic. Consuming exits and final carrier drops that can no longer return the obligation abandon it conservatively, without a free or a refund, and the lowest carrier records one `abandoned_releases` event. The counter is a saturating `u64` on Rust `BudgetSnapshot` and `MemoryScopeStats` (struct literals must add it) and `abandoned_releases: int` on every Python memory scope. It is history rather than a live leak count, and an abnormal same-user SHM peer can raise it with invalid, replayed or stale coordinates.

Prepared SHM replies hand buddy release authority to the receiver once the complete frame is written, before flush, so a later flush error, deadline or cancellation no longer frees peer-visible storage locally. Trailing-inline, chunked and discarded peer requests release through one carrier instead of a path that reported errors as success; pending responses and the chunk registry stop retrying real release errors. Python attaches a cleanup failure to the primary exception's context chain and, from 3.11, as a note. Low-level Rust gains consuming `abandon(self)` on Core `HeldResponse`, `ResponseLease`, `RequestLease`, `ReassemblyBacking` and `BudgetReservation`, `has_pending_release()` on Core `HeldResponse`, `MemoryBudget::record_abandoned_release()` and `LocalWriteHalf::write_all_with_progress()`. `c2_server::cleanup_request` and `Connection::ensure_peer_segment` are removed without aliases. C/FFI ABI 6, IPC 14, SHM 3 and business frames are unchanged.

Generated Rust, Python and TypeScript clients, and the shared TypeScript transport, no longer discard a cleanup failure that follows a decode, spec-hash or transport error: the primary error is still returned, and the cleanup failure is reported as a stderr or console warning. Generated Rust code calls the hidden `c_two::generated::release_held_after_error` helper; a failed native release stays with the high-level `Held` for its final drop.
