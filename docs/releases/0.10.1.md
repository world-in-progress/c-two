# C-Two 0.10.1

Status: release candidate; publication and the final validation record are pending. This patch keeps `cc.serve()` running when stdout cannot encode its messages, reported during adoption of 0.10.0. It continues to use FastDB 0.2.4 and the existing c3 0.6.0; no new CLI, Rust crate or npm package is published by this patch.

```bash
uv pip install --upgrade 'c-two==0.10.1'
# For FastDB Payload contracts:
uv pip install --upgrade 'c-two[fastdb]==0.10.1'
```

## `cc.serve()` output on non-UTF-8 stdout

Previously, the startup banner used box-drawing and bullet characters and the shutdown message an ellipsis, all written with `print()`. When stdout could not encode them, `cc.serve()` raised `UnicodeEncodeError` and the process exited with status 1. This happens on Windows when the server's output goes to a pipe or file and Python uses the system ANSI code page (for example cp1252 or GBK) instead of UTF-8 mode, and on POSIX under a non-UTF-8 locale. The shutdown message was written before `shutdown()`, so the error also skipped graceful shutdown.

The banner and the shutdown messages now use ASCII text and are written with stdout's own encoding: a route name that stdout cannot encode appears as `\uXXXX` escapes instead of raising. Each message is flushed, so a piped banner appears immediately. The wording is unchanged apart from the decoration characters (`-` rules and bullets, `...`).

## Compatibility

IPC handshake 14, Unix namespace format 3 and credential schema 4, C/FFI ABI 6, SHM 3, owner-control encoding 1, business frames and CRM hashes are unchanged, so 0.10.1 and 0.10.0 peers interoperate. Only the Python package changes.

The distribution matrix remains 35 wheels and one sdist. Windows ARM64 covers CPython 3.11, 3.12, 3.13, 3.14 and 3.14t; the other five platform targets retain Python 3.10 as well.

## Validation

The fix was accepted on `51cb141e`: the new tests fail on the 0.10.0 code under cp1252, GBK and ASCII stdout and pass with the fix, including a subprocess `cc.serve()` started without UTF-8 mode and, on Windows, under the default code page. Package qualification, receipts and publication run from `main` after the release pull request merges; they are pending and will be recorded here.
