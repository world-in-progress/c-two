# C-Two 0.7.5

Python C-Two 0.7.5 pairs with c3 0.3.4. Publication uses the exact artifacts retained by the successful release-candidate and source-validation gates.

## Python dependencies

Ordinary Python CRM calls need only the C-Two wheel. Importing C-Two, defining a
CRM, registering, connecting and calling with ordinary Python values do not
import `fastdb4py` or NumPy. FastDB Payload contracts opt in:

```bash
uv pip install 'c-two==0.7.5'
uv pip install 'c-two[fastdb]==0.7.5'  # only for FastDB Payload contracts
```

The extra pins `fastdb4py==0.2.2` to select this tested binding version. Missing
FastDB dependencies produce an error naming `c-two[fastdb]`. Python-only pickle
calls and the native byte interfaces remain available without the extra. The
workspace dev group selects the extra so the complete suite still tests payloads.

Python FastDB 0.2.2 is separate from the unchanged native FastDB Core 0.2.1
source/Rust pins. Deployable C-Two extension and c3 builds statically link that
Core; removing Python dependencies does not remove their native build tools.
Source installs require Rust and the C++/CMake tools used by the existing build.

## Outgoing IPC shutdown

A responsive peer can acknowledge DISCONNECT immediately. An unresponsive peer
gets at most 100 ms per outgoing connection for the combined disconnect write
and ACK, bounded by the existing total shutdown deadline. This preserves normal
protocol closure without spending the server work-drain budget waiting for a
stopped peer. Multiple connections still share the existing aggregate deadline.
No extra background waiter is created.

The result adds `ipc_clients_abnormally_closed` and `ipc_client_close_details`,
whose entries contain `address` and `reason`. A missing ACK can be reported as
`disconnect_ack_timeout`; write failure/timeout and peer EOF are also recorded.
`completed` and `ipc_clients_drained` retain their local cleanup meanings, so
callers must inspect the new details to distinguish local completion from a
normal protocol close. Server-side active-call drain, caller timeout semantics
and retained payload ownership are unchanged.

The shutdown result includes abnormal concurrent connection cleanup observed
during the drain, including completion between retries of the same shutdown
transaction. Distinct connections are counted separately even when they share
an address; completed closes from earlier transactions are not replayed.
Reporting retains only temporary close metadata and does not extend payload
or client ownership.

## Shutdown hooks

Declare `@cc.on_shutdown` on the CRM contract. The resource implements that
method as an ordinary method. Registration now rejects an implementation-only
shutdown marker, including a marker on an ordinary RPC method that was not
declared as the contract's shutdown hook. Valid hooks still run exactly once.
This check runs before creating the native server.

## Upgrade boundaries

The three release fixes do not change CRM descriptors, CRM ABI hashes or
signature hashes. Existing applications with unchanged business contracts do
not need to change their CRM version solely for these fixes. Adding fields to
the local shutdown outcome does not enter the CRM descriptor.

This release also includes the already accepted runtime and SDK cleanup since
0.7.4. The exact allocation identity repair changes buddy SHM format to 3,
IPC handshake to 12, and C/FFI ABI to 5. Upgrade communicating clients,
resource hosts, relays, native libraries and generated consumers together.
There is no old wire/ABI compatibility path; do not use published c3 0.3.3
with this source candidate. These transport versions are distinct from a
business CRM's ABI/signature fingerprints.

Other accepted source API cuts include owned `Vec<u8>` input for Rust
`EncodedService::invoke`, flat Rust IPC overrides without `BaseIpcConfigOverrides`,
removal of stored Rust `max_pool_memory` and peer handshake shadow state,
retirement of obsolete Python wire/handshake projections and three Python
`call_prepared` entries, the obsolete transfer `buffer` keyword, and generated
TypeScript Node IPC factories/types. Regenerate/recompile affected consumers;
use the official connector through generic connection injection. HTTP discovery
uses the strictly checked response header as namespace authority.

Socket locations, endpoint identity checks, owner lifecycle policy, allocation
rounding, trim release capacity and memory budget accounting retain their
accepted behavior. On macOS, the accepted default coordination-record migration
keeps coordination records outside automatic temporary-file cleanup while
sockets stay in their original temporary namespace. Historical endpoint files
are not migrated or deleted by this preparation.

The [local preparation report](../acceptance/0.7.5-preparation.md) records the
combined validation, RSS and frozen-peer measurements, ARM64 container proof,
and unverified platform/release gates. Earlier CI records remain evidence for
their own source commits, not for this candidate.
