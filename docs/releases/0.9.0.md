# C-Two 0.9.0 and c3 0.5.0

Published on 2026-10-25: [C-Two 0.9.0](https://pypi.org/project/c-two/0.9.0/) and [c3 0.5.0](https://github.com/world-in-progress/c-two/releases/tag/c3-v0.5.0), from source `3f223d658117511073ae549565ad2c49af163a87`. All 35 wheels, including five Windows ARM64 wheels, and the sdist are published. See the [validation and cleanup record](../acceptance/2026-10-25-090-windows-release-acceptance.md). FastDB stays at 0.2.3. Rust crate and npm package versions keep their independent release cadence.

## Windows user scope and server identity

Windows local IPC now uses the current process's TokenUser SID instead of its logon SID. One user's SSH, console, RDP and scheduled-task logons derive the same logical endpoint and namespace. Pipe and mapping DACLs admit that user; remote pipe clients remain rejected. The machine-wide listener lease uses a user-restricted Global mutex, so two sessions cannot own the same listener. Closing the listener still permits restart while old client stream handles exist.

Before any handshake, call, ping, shutdown or owner-recovery bytes, the native connection layer verifies the actual pipe object owner and its server process's TokenUser and integrity. A server must be at least Medium integrity; Low and Untrusted servers are refused even when their user SID matches. Medium and High peers can connect across logons. The process handle remains pinned while the connection is usable. Identity refusals use permission-denied, without inventing an OS error or treating the endpoint as missing. Owner inspection now retains `identity_mismatch`; a commit refused before sending retains `not_sent` with that cause. Node distinguishes `IDENTITY_MISMATCH` from an ordinary OS `PERMISSION_DENIED` failure.

A listener first grants its own user read-only access to its process identity/exit state and primary token. These process-lifetime ACEs allow a Medium peer to verify a High service; existing ACEs are preserved. No process-control, memory-write, token-duplication or impersonation permission is added. Same user plus sufficient integrity authenticates this local boundary, not a particular application binary; namespace occupation can still cause denial of service.

Mappings remain session-local and do not require Global mapping privileges. Native pipe session facts and directional handshake capabilities decide whether a peer can use SHM. Across sessions, normal and prepared requests/responses use existing owned, inline or chunked transfer. Unnegotiated SHM references are rejected before mapping or cleanup can open them. Budgets, retained snapshots, allocation identity, lifecycle policy and no-retry-after-dispatch behavior remain.

## Coordinated protocol and API cut

- IPC handshake **13** negotiates request and response SHM directions separately; handshake 12 is rejected. Business-frame layouts and CRM hashes are unchanged.
- C/FFI ABI **6** requires the verified Windows connection entry and adds permission-denied status 6 and identity-mismatch status 7. Existing allocation descriptors retain their layout. Old ABI libraries and opaque contexts are rejected.
- SHM header **3**, owner-control encoding **1** and EndpointCredential JSON schema **1** remain. Windows credential JSON denotes a logical endpoint in the current user scope; it does not persist an explicit SID guarantee.
- Rust `LocalEndpointContext::windows_logon_scope_id()` becomes `windows_user_scope_id()`. `c2_local_security::current_logon_sid()` is replaced by `current_user_sid()`; `current_scope_id()` now hashes TokenUser. Recompile consumers.
- The official Windows Node connector uses native verification and a transferred Node-owned descriptor. Windows `createConnection`, `resolveEndpoint` and `nativeSymbols` overrides are rejected; inject a real captured endpoint context when needed. Unix injection remains available. Generic generated transport injection retains the caller's transport-authentication obligation. HTTP-only use still loads no native runtime.

Stop cooperating services, upgrade clients, hosts and c3 together on every OS, then restart for IPC 13 and ABI 6. Windows also changes endpoint names and owner-context binding. No old endpoint name, logon binding, ABI or handshake fallback is attempted. Owner tickets use a new user-scope context domain; old logon-bound tickets do not authorize the new context. Fresh recovery tickets may be transferred between the same user's logons under the existing one-use, epoch and grace rules.

## Python buffer lifecycle synchronization

Serialize Python buffer export admission with release through the existing native locks. A view that wins the race now prevents response invalidation or request release with the existing `BufferError`; a release that wins prevents new exports. Request retained tracking can no longer install a statistical lease after release. Snapshot storage, error types, release ordering, idempotency and all public APIs, ABIs and protocols remain unchanged.

## Python manual assembly API retirement

Remove `c_two.mem.ChunkAssembler`, `c_two.mem.MemHandle` and their `_native` exports. These were the manual Python entry points used by the retired Python transport loops. They have no compatibility aliases or replacement Python manual-assembly API. Code that directly constructed an assembler and accessed its finished handle must move to normal RPC automatic chunking or the retained Rust assembler API.

The Rust `ChunkRegistry`, `ChunkAssembler`, `ReassemblyBacking` and `MemHandle` remain unchanged. Current IPC chunking, memory-pool APIs, snapshots, budget accounting and release order are preserved. This retirement itself leaves transport representations unchanged; the release-wide protocol cut is described above.

## Inline response ownership

Core now moves an IPC inline response's existing byte vector into the held response owner. Ordinary Python IPC calls and Rust held calls avoid one payload allocation and copy; Rust owned calls retain their existing move path. SHM and chunked responses keep their original transport leases, pool identity, budget accounting and release order. Python snapshots and FastDB receive adapters retain their existing behavior. Public APIs, ABI and protocols are unchanged.

## Python endpoint credentials

`cc.EndpointCredential` now exposes the existing frozen native type directly. `cc.inspect_endpoint` passes the observed Rust credential to Python without encoding JSON, parsing it again or allocating a Python wrapper. `cc.reap_endpoint(address, credential)` accepts that same value. Metadata properties, `from_json(document=...)`, `to_json()` and the public repr are preserved.

Remove uses of the old `EndpointCredential(native)` wrapper constructor, subclassing, `credential._native`, `copy.copy(credential)` and `_native.PyEndpointCredential`. Share the immutable value directly within a process. The low-level `_native.inspect_endpoint_endpoint` present result now contains a credential object instead of a JSON string. There are no compatibility aliases. Python method descriptors and non-string argument diagnostics now come from the native type.

For persistence or cross-process transfer, call `to_json()` explicitly and restore with `cc.EndpointCredential.from_json(document=...)`. These boundaries retain strict schema/platform/field validation, canonical JSON and the 32 KiB limit. Inspection reports the observed native object without also promising that JSON export will succeed; a subsequent explicit export can report its codec error.

This credential projection does not change Rust public APIs, SHM 3, owner control 1, business frames or credential JSON formats. Exact identity checks, reaping authority and lifecycle behavior are unchanged. This credential projection is included in the published 0.9.0 release.
