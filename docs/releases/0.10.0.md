# C-Two 0.10.0 and c3 0.6.0

Published on 2026-10-30: [C-Two 0.10.0](https://pypi.org/project/c-two/0.10.0/) and [c3 0.6.0](https://github.com/world-in-progress/c-two/releases/tag/c3-v0.6.0), from source `4b1d91610fd1a0745cea0b5bb841ab0928ed723b`. All 35 wheels, including five Windows ARM64 wheels, and the sdist are published. See the [validation and cleanup record](../acceptance/2026-10-30-0100-release-acceptance.md). C-Two 0.10.0 depends on FastDB 0.2.4. Rust crate and npm package versions keep their independent release cadence.

## Coordinated protocol and format cut

- IPC handshake **14** opens every RPC connection with a fixed version preamble and reports a version mismatch as a typed error. It cannot interoperate with 0.9.x and older peers, which speak IPC 13 or earlier.
- Unix namespace disk format **3** uses versioned default directories, and Unix `EndpointCredential` JSON moves to schema **4**. Windows keeps its kernel-managed schema 1.
- C/FFI ABI 6, SHM header 3, owner-control encoding 1, business-frame layouts and CRM hashes are unchanged.
- Building from source requires Rust **1.95** or newer.
- Rust public types and signatures listed below change; recompile and update Rust consumers.

Upgrade the Python and Rust SDKs, c3 and Node consumers on one host together, after every old process has stopped. The new build neither reads nor deletes old default directories, and no old handshake, namespace format or credential schema is accepted.

## IPC version diagnostics

The RPC IPC handshake moves from 13 to 14 and now opens with a permanent fixed 25-byte version preamble (`C2IP`, directional flags `0x04`/`0x06`, nonzero `u32` version) before any variable metadata; the one-byte version fields in the request/response metadata are removed. A complete `VersionMismatch` preamble is a typed error carrying both versions; malformed or truncated records keep the existing decode/protocol classifications and never fabricate a peer version. Server admission fences un-negotiated CALL/ordinary-CTRL frames, duplicate handshakes and mid-connection role changes; identity checks still precede the preamble, and one shared connect budget covers both exchanges.

New error surfaces: Python `CoreError` gains `category='protocol_version_mismatch'` with `local_protocol_version` / `peer_protocol_version` (`None` on every other error; `transport_phase='pre_dispatch'`, no OS cause fields); Rust adds `IpcError::ProtocolVersionMismatch { local: u32, peer: u32 }` and Core `Error::ProtocolVersionMismatch { local: u32, peer: u32 }` (exhaustive matches must add them); generated TypeScript `C2IpcTransportError` gains nullable `localProtocolVersion` / `peerProtocolVersion` plus `category`, keeping cleanup failures on `Error.cause`. Relay-local route acquisition treats the typed mismatch as terminal — local cleanup then rethrow, no route fallback, no HTTP fallback, no retry — while an HTTP relay's own upstream IPC mismatch still projects the existing `ProtocolViolation` (502) with version details naming the relay/upstream pair, not the caller's local end.

Pre-14 peers, including 0.9.x and older wheels, send no preamble, so mixing old and new ends remains a plain connection/protocol failure; an old wheel observes a generic connection failure with no typed projection. Low-level manual handshake callers must adopt the two-phase sequence; the old single-frame RPC handshake entry is removed. See the [handshake specification](../reference/ipc-handshake.md).

A successful new physical connection adds one local round trip and 48 net handshake bytes; calls on an established connection add nothing, and a version rejection costs one Hello/VersionMismatch round trip. The generated TypeScript relay-aware local path still rebuilds and closes its IPC transport per call and therefore pays the added round trip on every call. On the measured macOS host, a new-format rejection returned in 0.744 ms P50 / 0.914 ms P95; this is not a cross-platform latency guarantee. Mixed 0.9.0/new pairs were tested in both directions on macOS and Windows x64; Linux old-wheel mixing was not separately tested.

## Unix namespace identity and listener credentials

Unix endpoints use namespace disk format 3 and versioned default locations: `/tmp/c2-v3-<uidhex>` for sockets and, on macOS, `confstr(_CS_DARWIN_USER_DIR)/c2-ipc-coordination-v3` for gate/marker/lease records. Custom roots gain no suffix. Gate, marker and lease records share the format version; fixed magic `c2mgatv2` / `c2mgrec2` keeps its managed-v2 backend meaning. The gate remains 25 bytes, the marker becomes 33 bytes and the lease record's fixed header becomes 51 bytes. Persisted device fields and the redundant `RECORD_PROTOCOL` byte are removed. Live dev+ino checks and owner `context_digest`/domain remain unchanged. A recognizable other gate/marker version reports `unsupported-namespace-format` before adoption. Unix credential JSON moves to schema 4 without device and rejects all schema 3 documents.

Default directories for different formats are separate, so no same-path cold switch is required. Historical manual cleanup requires every old process to exit and be prevented from restarting. Explicitly sharing a custom physical root across disk formats is unsupported; if it reports `unsupported-namespace-format`, rebuild only after every user has exited, cannot restart and the whole root has been safely archived offline. Misconfigured cross-format roots retain identity checks that prevent deleting the other format's endpoint, while maintenance counts and reasons may be inaccurate.

An unverifiable Unix bind now retains its native `InvalidData` refusal and reports Python `CoreError.endpoint_unverified_reason` using the same finite strings as endpoint inspection; `io_kind` is `other` and no errno is fabricated. Actual OS errors retain their kind and errno. Exhausted coordinator-gate waiting is `WouldBlock`; a live address or listener lease remains `AddrInUse`. Rust introduces `EndpointBindCause { error, unverified_reason }`, uses it in `LocalIoCause::Bind`, and renames the readiness failure field to `ServerFailure.bind_cause`; `EndpointIoError` and Connect/sweep error shapes stay unchanged. Rust callers matching these public types must update their code.

Python adds `cc.server_credential() -> EndpointCredential | None`. It reads the current listener credential from the existing lifecycle watch without inspection, I/O, a namespace gate or a readiness wait. Ready and Stopping with a retained listener return the credential; before start, after bind failure and in terminal Stopped/Failed states it returns `None`. The old snapshot can remain visible between run cancellation and lifecycle finalization. It does not prove liveness or grant cleanup or owner authority. Windows returns a kernel-managed schema 1 credential while inspect/reap remain not applicable. See the [lifecycle guide](../reference/local-endpoint-lifecycle.md).

## Endpoint maintenance I/O errors

A missing-lease sweep slot whose socket stat fails increments `io_errors` and retains `last_io_error`, instead of counting an unobserved slot as already absent. Inspection retains an error from the final lease stat; a socket identity already known to differ still takes precedence. The existing Python `io-error` projection includes kind/errno and `retryable=True`; no retry is added. CLI sweep `complete` still means directory EOF, so callers must also inspect its error counts.

Shared Unix lease verification and record reads preserve I/O errors. Inspect, reap, sweep and explicit listener close retain the original error instead of reporting `InvalidOwnership`; sweep uses its existing `io_errors`/`last_io_error` fields. Bind passes through those OS failures while retaining `InvalidData` and the original message for policy refusals. The server's existing close-result mapping consequently reports `ServerError::Io` rather than `Config` for these failures, with the same Failed lifecycle state and release order. Verified deletion classifies a real I/O error from the final lease stat as the existing `IoError`; an identity mismatch still refuses deletion.

## Independent Python runtimes

`cc.Runtime()` directly exposes an independent Python binding owner over its own native session; module-level registration, connection, configuration, observations and shutdown continue through the default Runtime. Instance `start()` can wait for an empty Host's existing readiness/PONG, while later `register()` uses that Host. Instance code overrides do not inherit the default Runtime's overrides; environment and `.env` remain shared native resolver inputs. Instance-local name lookup does not search another Runtime's local routes, and cross-instance IPC uses an explicit address and matching Unix endpoint context. `cc.close(proxy)`, `cc.hold()` and call-option views retain their proxy owner. `cc.serve()` still owns signals only for the default Runtime; explicit instances require caller-managed shutdown, with no `Runtime.serve()` or automatic custom-directory deletion. After completed shutdown, the Python object receives a fresh native session under existing handoff rules, and old event subscriptions remain bound to the old source. See the [independent runtime example](../../examples/python/independent_runtime.py).

`Runtime.shutdown()` / `cc.shutdown()` start one permanent Core retirement scope, separate from Host shutdown. A pending result requires a later SDK shutdown to observe completion and replace the session. The caller's wait deadline does not cancel the cleanup driver; failure before handoff is a structured `shutdown_wait_timeout`, not pending. New start, registration and remote connections stay refused until the completed receipt is consumed. Low-level Rust/Native Host restart behavior and normal pooled connection reuse remain unchanged, and final connect publication uses the original connect deadline without retry.

Failed-start cleanup observations now refer to the concrete failed Server transaction, retaining pending state and terminal errors instead of selecting an empty or old Host result. Existing Rust host signatures stay unchanged; Core adds the read-only `FailedStartShutdownReceipt` and `host_with_failed_start_receipt` projection.

## Failed memory releases

Explicit low-level Rust releases keep their ownership on failure. `MemPool::release_handle` now returns `Result<FreeResult, ReleaseHandleError>`: buddy release failures are reported with the original `MemHandle`, rather than consumed or reported as success. `SyncClient::pool_alloc_and_write/fill` returns `RequestPreparationError`, retaining any block whose preparation cleanup failed; the block can only be cleaned up, never recovered for publication. `pool_free` returns `Result<(), IpcError>`. `RequestLease::release` and `ResponseLease::release` keep their original carrier on failure and clear it on success, preserving storage-before-reservation release. Exhaustive return-type annotations and error handling must migrate; no old signatures or aliases remain.

An explicit native cleanup failure keeps the original lease, budget charge and concrete connection pin with its holder: Core `HeldResponse`, Rust `Held::release()` and Python `HeldResult.release()` can be called again, and the FastDB invalidator runs at most once, including after a raised error or panic. Consuming exits and final carrier drops that can no longer return the obligation abandon it conservatively, without a free or a refund, and the lowest carrier records one `abandoned_releases` event. The counter is a saturating `u64` on Rust `BudgetSnapshot` and `MemoryScopeStats` (struct literals must add it) and `abandoned_releases: int` on every Python memory scope. It is history rather than a live leak count, and an abnormal same-user SHM peer can raise it with invalid, replayed or stale coordinates. See the [memory policy](../reference/memory-policy.md).

Prepared SHM replies hand buddy release authority to the receiver once the complete frame is written, before flush, so a later flush error, deadline or cancellation no longer frees peer-visible storage locally. Trailing-inline, chunked and discarded peer requests release through one carrier instead of a path that reported errors as success; pending responses and the chunk registry stop retrying real release errors. Python attaches a cleanup failure to the primary exception's context chain and, from 3.11, as a note. Low-level Rust gains consuming `abandon(self)` on Core `HeldResponse`, `ResponseLease`, `RequestLease`, `ReassemblyBacking` and `BudgetReservation`, `has_pending_release()` on Core `HeldResponse`, `MemoryBudget::record_abandoned_release()` and `LocalWriteHalf::write_all_with_progress()`. `c2_server::cleanup_request` and `Connection::ensure_peer_segment` are removed without aliases.

Generated Rust, Python and TypeScript clients, and the shared TypeScript transport, no longer discard a cleanup failure that follows a decode, spec-hash or transport error: the primary error is still returned, and the cleanup failure is reported as a stderr or console warning. Generated Rust code calls the hidden `c_two::generated::release_held_after_error` helper; a failed native release stays with the high-level `Held` for its final drop.

The chunk registry skips an automatic pressure-triggered sweep while its previous complete sweep proves that no entry can have expired yet; explicit and periodic GC always sweep completely. No API changes.

## Build and dependencies

- FastDB 0.2.4 fixes memory release in standalone FastDB databases, numeric-column caches and mapped storage. The Python extra, Rust dependencies, statically linked native source and verified Core SDK upgrade together; portable payload semantics and the 117-symbol ABI are unchanged.
- All Rust workspaces move to `parking_lot` 0.13, which requires Rust 1.95. Every user-facing Rust package declares `rust-version = "1.95"`, so older toolchains fail with an explicit Cargo error. Prebuilt wheels and c3 binaries are unaffected.
- `c2-http` enables only the tokio features it uses instead of `full`.
- Lockfiles take the rustls 0.23.46 and msgpack 1.2.3 security updates.
- The Python grid example no longer depends on PyArrow: its unused Arrow file persistence (`grid_file_path` and `terminate()`) is removed, and the `examples` and `dev` dependency groups install only NumPy and pandas for it.
