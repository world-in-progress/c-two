# C-Two 0.8.2 and c3 0.4.1

This release repairs relay observer recovery and adds a shared client/server connection-event feed and public structured Python errors. It also ships the previously validated Node exchange fix and retirement of the unused Python `ShmBuffer` projection. FastDB remains 0.2.3. Rust crate and npm package versions keep their independent release cadence.

```bash
uv pip install --upgrade 'c-two==0.8.2'
# For FastDB Payload contracts:
uv pip install --upgrade 'c-two[fastdb]==0.8.2'
```

## One feed for physical IPC connections

Previously, `cc.connection_events()` observed only accepted server connections; a client needed one blocking `ConnectionObservation.wait_closed()` call per connection. Subscribe before connecting to observe managed outgoing and accepted connections through the same bounded feed:

```python
import c_two as cc

events = cc.connection_events()
try:
    worker = cc.connect(Worker, name="worker", address="ipc://worker")
    observation = cc.connection_observation(worker)
    event = events.recv(timeout=5.0)
    assert event.side == "client"
    assert event.connection_id == observation.connection_id
finally:
    events.close()  # also wakes a receiver blocked in another thread
```

`side` is `client` or `server`; `kind` remains `opened` or `closed`. Waiting releases the GIL. `close()` ends only that subscription, is idempotent and causes later `recv()` to raise `StopIteration`. Timeout returns `None`. A second simultaneous receiver is rejected; the queue remains bounded to 1024 events, and lag raises `ConnectionEventsLagged` then ends the subscription. There is no historical replay. An open event proves physical OS connection establishment, not handshake or resource readiness.

Logical proxy close does not report a physical disconnect. Shared clients keep the same connection ID; a new physical connection gets a new ID. Close reasons come from the original native receive/heartbeat/close authority and agree with `observation.snapshot()`. Notifications do not prove process death, callback drain or permission to replay requests. UDS and Windows Named Pipes use the same API.

Remove calls to Python `ConnectionObservation.wait_closed()` and use the event feed. Keep `connection_observation(proxy)` and `snapshot()` for ID association and late terminal inspection. The old Core blocking `wait_connection_closed()` bridge is removed. Rust's existing async observation wait remains the single-connection primitive used by native close barriers. Low-level Rust callers pass `ConnectionSide` to `ConnectionPublisher::new(side)` and `ConnectionEventSource::open_connection(side)`; the publisher's old `Default` constructor is removed. `ConnectionEvents::recv` now borrows `&self`, with explicit `close` and `ConcurrentReceive`.

## Public structured Python errors

Replace private `from c_two._native import CoreError` with:

```python
from c_two.error import CoreError

try:
    worker = cc.connect(Worker, name="worker", address="ipc://worker")
except CoreError as exc:
    print(exc.category, exc.io_operation, exc.io_kind, exc.raw_os_error)
    raise
```

`CoreError` now belongs to the public `c_two.error` module and shares `CCBaseError` with semantic `CCError`; it also remains a `RuntimeError`. The old native export and Python per-connection blocking wait have no aliases or compatibility paths. Every structured field is annotated and present on every instance. The [API field table](../reference/local-endpoint-lifecycle.md#public-structured-python-errors) documents each range, nullable OS codes, transport phases and transaction outcomes. Error classification, original diagnostic text, retry eligibility and call-stage wrapping retain their existing meanings.

## Relay observer recovery (R18)

Previously, reaching the relay's 1024 native-client-owner limit made an upstream control watcher exit permanently. Releasing capacity did not restore observation, and separate task/status locks allowed an old task to clear a replacement's unavailable record. The watcher now records temporary unavailability and uses its existing retry loop; permanent lifecycle shutdown still ends it. Task removal and status updates share the existing control lock and generation token. Unavailable records retain their independent lifetime, including across control-task shutdown. Route identity checks, unpublished/closing capacity accounting, live data-plane revalidation and release ordering are unchanged.

Use c3 0.4.1 for this relay fix. No new worker, retry policy, status framework or capacity increase is introduced.

## Other source changes since 0.8.1

- R16: Node chunked calls advance send and receive together. Failure closes and joins the exchange, retains the first confirmed error, and discards that connection; a later call reconnects. Successful calls continue reusing their connection, with no post-send retry. Low-level injected TypeScript connections must implement the current `close()` contract; socket adapters supply native `pause()` and `resume()`. Regenerate TypeScript artifacts and update custom low-level adapters directly. See the [R16 acceptance record](../acceptance/2026-10-23-r16-node-exchange-acceptance.md).
- The unconstructed legacy `_native.ShmBuffer` Python projection is removed. Current held/borrowed snapshots and exact release paths are unchanged; there is no compatibility constructor. See the [retirement record](../acceptance/2026-10-23-shm-buffer-retirement.md).

IPC handshake 12, SHM 3, C/FFI ABI 5, owner-control 1, business frames and CRM hashes are unchanged. Historical endpoint directories are not migrated or cleaned. The distribution matrix remains 35 wheels and one sdist, including five Windows ARM64 wheels for CPython 3.11–3.14 and 3.14t; other platform targets retain 3.10. Publication passed the complete exact-source gates and installed-candidate checks; the official files and installed wheel were verified. See the [release acceptance record](../acceptance/2026-10-23-082-client-observation-release-acceptance.md).
