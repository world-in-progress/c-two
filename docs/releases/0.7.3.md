# C-Two 0.7.3: endpoint directories

English · [简体中文](0.7.3.zh-CN.md)

Unix `root` selects the final endpoint directory. The default is `/tmp/c2-<uidhex>`; custom directories contain sockets directly as `<root>/<32-character id>`. Endpoint ids use the first 128 bits of SHA-256 of the logical server id, encoded as lowercase hexadecimal. There is no appended user directory, layout version or socket suffix.

```python
from pathlib import Path
import c_two as cc

root = Path('/Users/me/Library/Application Support/my-app/ipc')
root.mkdir(parents=True, exist_ok=True, mode=0o700)
cc.set_local_endpoint(root=str(root))
```

Applications provision custom directories with current-user ownership and mode `0700`. C-Two initializes its default directory, manages its own endpoint/lease/coordinator files, and retains the application directory and unrelated files. Code/CLI overrides precede process environment, `.env` and native defaults. Resolution preserves Unicode and spaces and performs no filesystem I/O. The first local I/O attempt freezes the context, including failure.

Linux and macOS use open directory descriptors to bind, connect and probe short endpoint names. The filesystem's directory-opening constraints determine usable root length; the socket-address field no longer limits the full displayed path. Linux uses its existing `/proc/self/fd` mechanism. macOS initiates nonblocking connections on a short-lived thread with a private working directory, then completes them on the caller's reactor. Node Unix connections use the same native transport and transfer an owned connected descriptor to Node. Windows continues to use current-logon SID Named Pipes and rejects Unix root overrides.

Unix credentials use existing schema 3 for both default and custom directories, with the final root and namespace id. Encoding, decoding and CLI file reading share a 32 KiB bound. Windows keeps kernel-managed schema 1. Obsolete Unix directory derivation and schema-2 reconstruction are removed directly; processes in the same communication group use matching builds. Existing endpoint directories and historical files are not automatically migrated or swept.

Full identity, route-contract, coordinator, lease, incarnation and exact-cleanup checks remain in force. Listener shutdown, native work drain and retained payload release are separate lifecycle observations. See the [configuration guide](../configuration.en.md), [lifecycle guide](../local-endpoint-lifecycle.en.md) and [implementation design](../designs/0.7.3-local-endpoint-paths.md).
