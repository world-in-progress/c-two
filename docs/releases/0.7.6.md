# C-Two 0.7.6

Python C-Two 0.7.6 pairs with c3 0.3.5. This patch fixes an outgoing IPC
shutdown-report race discovered after 0.7.5 was published.

A concurrent connection attempt can finish its cleanup after the shutdown
coordinator removes completed records, but before it builds the final report.
Previously, the final filter excluded only connections still being prepared,
so it could label an already confirmed record as an unconfirmed close. A
client-only runtime could consequently return `ipc_clients_drained: false`
with that address in `ipc_client_close_error`, despite cleanup having finished.

The final report now selects only records whose close is running or whose
previous close was unconfirmed. The original concurrent acquire/close test
is retained. A controlled reproduction of the completion between the two
state observations fails on 0.7.5 and passes with this correction.

The 100 ms outgoing disconnect/ACK bound, server work drain, shutdown timeout,
abnormal-close details, identity checks, memory ownership and release order
are unchanged. This patch adds no compatibility entry point or dependency.
Ordinary Python calls still need no Python runtime dependencies; FastDB
contracts use the optional `c-two[fastdb]` extra with `fastdb4py==0.2.2`.

```bash
uv pip install --upgrade 'c-two==0.7.6'
# For FastDB Payload contracts:
uv pip install --upgrade 'c-two[fastdb]==0.7.6'
```

Public Python and Rust signatures, CRM descriptors and ABI/signature hashes,
SHM format 3, IPC handshake 12, and C/FFI ABI 5 are unchanged from 0.7.5.
Applications do not need to bump their business CRM version for this patch.
See [0.7.5](0.7.5.md) for the format and source API changes when upgrading
from 0.7.4.

Publication promotes the exact artifacts from the successful same-source
main-branch Source Validation and Release Candidate runs. Version 0.7.5
remains immutable; this release does not replace its files.
