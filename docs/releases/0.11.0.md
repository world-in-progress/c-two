# C-Two 0.11.0 and c3 0.7.0

Published on 2026-11-20: [C-Two 0.11.0](https://pypi.org/project/c-two/0.11.0/) (35 wheels, including five Windows ARM64 wheels, plus 1 sdist) and [c3 0.7.0](https://github.com/world-in-progress/c-two/releases/tag/c3-v0.7.0) (6 platform binaries, 2 installers and provenance manifest), from canonical `main` commit `50be9a7966d6c8381715809440d69502c3cee5de` (FastDB **0.2.4**, Rust **1.95+** for source builds). See the [0.11.0 release acceptance record](../acceptance/2026-11-20-0110-release-acceptance.md). Rust crate and npm package versions keep their independent 0.1.0 cadence.

This release brings **single-owner shared-memory release**, **server streams** (same-process, direct IPC and relay HTTP), **route-name identity**, **role-domain `(M, F, N)` capacity configuration**, **Node clients backed directly by the Rust Core client (C/FFI ABI 8)**, and a **converged public API and error hierarchy**. Intermediate protocol revisions `IPC 15` and `C/FFI ABI 7` were never published; this guide describes the direct upgrade from **C-Two 0.10.1 / c3 0.6.0** to **C-Two 0.11.0 / c3 0.7.0**.

## Upgrade together

- **Protocols and ABIs:** IPC **16** (replaces 14 in 0.10.x), SHM **4** (replaces 3), C/FFI ABI **8** (replaces 6) and relay mesh **7** (replaces 6). Unix namespace disk format **3**, Unix `EndpointCredential` schema **4**, `C2E1` v1 error wire format and FastDB **0.2.4** are unchanged.
- **Stop and upgrade peers together:** 0.10.x peers receive a typed `ProtocolVersionMismatch` through the unchanged fixed IPC preamble; 0.9.x and earlier peers see a generic connection or protocol failure. Stop running hosts and relays, then upgrade the Python SDK, Rust SDK, `c3` and Node binding on one host — and all relays communicating within the same mesh — together and regenerate generated Rust, Python and TypeScript contract clients.
- **No compatibility shims:** All retired names, environment variables, error subclasses, owner APIs and legacy ABI/wire entries are removed without aliases.

   - Update `memory_stats()` consumers to symmetric `client`, `server`, `retired` and `holds`, and `call_execution_snapshot()` consumers to call-slot counters under `client`, `server` and `retired`.
3. **Error hierarchy and `transport_phase`** ([details](#error-surface-and-retired-helpers)):
   - Replace Python `ERROR_Code` with `c_two.error.ErrorCode` (Rust variant names, e.g. `ErrorCode.CallCancelled`), `ResourceExecuteFunction` with `ResourceExecutionError`, the six codec/buffer `side × stage` subclasses with `SerializationError` (inspecting `.side` and `.stage`), and `ClientCallResource` / `RegistryUnavailable` / `RouteWatchUnavailable` with base `CCError`.

   - Regenerate Rust, Python and TypeScript clients; rebuild Node bindings against C/FFI ABI 8 and migrate `createNodeIpcConnect` to `createNodeIpcConnector`.

## Configuration and capacity

Capacity is configured per role ([configuration](../reference/configuration.md), [memory policy](../reference/memory-policy.md)). A Runtime lazily creates an independent `client` domain on first remote business use and a `server` domain on Host startup; a standalone relay creates one `relay` domain. Each domain's memory budget `M` and file spill budget `F` default to 16 GiB; its outstanding-call limit `N` defaults to `0` when `M == 0` and `max(64, floor(M / 65536))` otherwise. Positive `N` requires positive `M`. Every remote business call (including unlimited unary calls) counts toward `N`; same-process Python calls count against the target Host. Rust and Python direct IPC and relay HTTP calls, as well as generated TypeScript direct IPC calls, wait without a default call deadline; generated TypeScript explicit relay and relay-aware transports default `callTimeoutMs` to `300000` ms (`callTimeoutMs: 0` disables it).

The `C2E1` v1 wire format and canonical numeric error codes (`0`, `1..=8`, `701..=719`, with `704`, `706` and `711` permanently retired) keep their numbers, while `(side, stage)` metadata and `transport_phase` now have one authority in Rust Core ([errors reference](../reference/errors.md)).

Outer transport facts take precedence in Core, Python and C ABI 8; errors escaping a resource method that already ran strip inner call-control entries onto fresh projections without mutating caller exceptions.
- **Rust SDK root exports:** `c_two` re-exports `ErrorCode`, `ErrorSide`, `ErrorStage`, `C2Error` and `TransportPhase`.
- **Accurate server attribution:** `c2-server` reports pre-dispatch unknown-method and request record/storage refusals as `ProtocolViolation` (`713`, `NotExecuted`) instead of codes `3` or `1`, and post-execution unary response capacity exhaustion as `CallCapacityExceeded` (`717`, `Failed`) instead of code `2`. ## Smaller public surface

The Python `c_two` root and Rust `c_two` crate root keep only everyday runtime, contract, registration, call, configuration and error APIs ([interface review](../design/2026-10-31-api-surface-review.md)).

## Single-owner shared-memory release

Each shared-memory block has a single owner ([ADR 0001](../decisions/0001-single-owner-release.md)). The owner lends a block; the receiver copies bytes into local memory and returns the loan immediately after the copy — before a resource method runs on requests, and before decoding or delivering a `cc.hold` on responses.

- Over remote transports (IPC and relay HTTP), `cc.hold` and borrowed inputs keep local copies; `HeldResult.release()` invalidates the payload owner once and frees the copy without transport-memory release failures (on the same-process direct path, `cc.hold` returns `HeldResult(result)` wrapping the original Python object without transport copies, FastDB invalidation or `holds` accounting). `abandoned_releases` is removed from `memory_stats()`; `holds` reports `active_holds`, `total_held_bytes`, `oldest_hold_seconds` and `by_direction`.
- A peer that stops while still holding loans keeps those loans until it releases them or its connection ends; shutdown returns `completed=False` when its wait budget expires and continues retiring in the background without freeing loaned blocks prematurely.
- **Dispatched calls are never abandoned on C-Two's own initiative:** deactivation, eviction, route unregistration, relay shutdown and `Runtime.shutdown()` stop new calls while letting unary calls already sent finish and deliver their results. Waiting budgets are validated consistently across Linux, macOS and Windows.
- `cc.connect(timeout=...)` (and TypeScript `connectTimeoutMs`) also bounds the OS connection, namespace gate or pipe wait, and handshake. `cc.serve(shutdown_timeout=30.0)` validates the budget on entry, invokes shutdown once and returns the outcome.
- Direct IPC `shutdown()` returns `'initiated'`, `'absent'` or `'unconfirmed'` (a 1-byte ACK visible only after admission is closed on every connection); host lifecycle snapshots report `finished`, `listener_closed` and `work_drained`.
- **IPC 16 call records:** `OPEN`, `CALL_END`, `RELEASE` and server-stream records replace IPC 14 business frames. Writer tasks assign 64-bit request IDs in wire order; high-water marks discard late chunks of finished/refused calls; pre-dispatch server refusals end as `NotExecuted` with `transport_phase=pre_dispatch` instead of resource errors; chunked IPC calls reserve routes in frame order at their first chunk.

## Server streams

Methods can now return server streams ([ADR 0003](../decisions/0003-server-streams.md), [Python server streams](../reference/python-usage.md#server-streams), [Rust SDK](../../sdk/rust/README.md#server-streams), [HTTP streams](../reference/contracts-and-routing.md#server-streams-over-http)):

- **IPC 16 transport & `CallCancelled` (718):** Streams move as `ITEM_BEGIN` / `ITEM_DATA` with receiver-granted `CREDIT` and cause-bearing `CANCEL` (`Consumer` or `Lifecycle`). `OPEN` carries the call mode (unary or server stream); mismatched calls are refused before dispatch using existing error code `UnsupportedCallMode` (716): over relay HTTP, an ordinary request to a stream method returns HTTP 406, whereas a request with the stream `Accept` header to a unary method returns HTTP 200 whose sole record is a `NotExecuted` `CALL_END` with code 716.
- **Rust & Python SDKs:** Python adds `@cc.stream`, `cc.Stream` (`close(timeout=30.0)`), `cc.hold(...)` streams, same-process object streams (preserving `contextvars`/`decimal` context across worker steps) and generated stream methods; Rust generates `ResponseStream<fastdb::Payload>` / `Held` clients and `Service` iterators. Python and Rust stream to each other over direct IPC and through relays.
- **Lifecycle:** Route unregistration, Runtime shutdown and relay shutdown end open streams between steps: the running step finishes, produced items are delivered, cleanup runs, and the stream ends with `CallCancelled` naming the cause. Every stream holds an `N` call slot until its real terminal.
- **Relay HTTP streams:** Relays forward unary and stream responses one reusable download window slice at a time without assembling whole bodies first. `DELETE /_calls/{token}` cancels a stream while preserving its real terminal frame; dropping the HTTP body cancels upstream after releasing local payload and window reservations. Note that HTTP carries no per-item `CREDIT`, so a resource behind a relay can run ahead of a paused consumer by what HTTP and TCP buffers hold (use direct IPC when strict step-by-step backpressure is required). Generated TypeScript clients consume server streams over direct IPC and relay-selected local IPC, and refuse relay-HTTP stream methods before dispatch with `UnsupportedCallMode` (716).

## Route name identity

A route name together with its contract identity is now the sole identity of a resource's state ([ADR 0004](../decisions/0004-route-name-identity.md)).

- **Clients follow the route name:** When a client knows its target is gone (peer disconnect/reset or pre-dispatch route refusal), its next call re-acquires the route by name within the call's deadline — direct IPC reconnects to the address, relay-aware clients re-resolve at their anchor (moving between local IPC and relay HTTP as needed), and Python same-process proxies re-resolve locally then via relay. Calls already sent finish where sent and are never replayed; a call that learns of a move from its own pre-dispatch refusal fails retry-safely so the caller decides.
- **Mesh uniqueness and conflict visibility:** Relays refuse a duplicate registration of a name already held in the mesh. Unreachable (`Suspect`/`Dead`) relays retain their registrations (answering `ResourceUnavailable` 702 / `ResourceAlreadyRegistered` 703 with holder `registrations` metadata) until recovery, `POST /_admin/unregister` or **`c3 registry force-leave <relay-id> --relay <url>`** (`POST /_admin/force-leave`). If a healed partition or concurrent registration race leaves multiple live holders, new acquisitions fail before dispatch with **`RouteConflict` (719, HTTP 409)** listing all holders; `c3 registry list-routes` marks conflicts explicitly.
- **Removed:** Route UIDs on client surfaces (`route_uid`, `ObservedRoute`, `observed_route()`, `x-c2-route-uid`, plus unreleased intermediate ABI 8 route token/`routeUid`), error codes `704 RouteStale`, `706` and `711`, the Runtime's shared relay resolution cache, and TypeScript `maxAttempts` / `routeCacheTtlMs`.

## Node clients on the Rust client (C/FFI ABI 8)

Generated TypeScript clients now invoke the Rust `c2-core` client through **C/FFI ABI 8** instead of framing IPC in TypeScript ([C ABI](../reference/c-abi.md), [TypeScript binding](../../core/foundation/c2-mem-ffi/bindings/typescript/README.md)):

- `createNodeIpcConnector` (replacing `createNodeIpcConnect`) owns one native client domain with shared capacity budgets (`memoryBudgetBytes`, `fileSpillBudgetBytes`, `maxOutstandingCalls`) and no-side-effect `connector.stats()`.
- Removal of the TypeScript `callChain` lets unawaited unary calls on one connection run concurrently (await calls when order matters). Relay-aware clients reuse one local IPC connection per server instance instead of reconnecting per call.
- Direct IPC and relay-selected local IPC support `C2ResponseStream` and `C2HeldResult` (`for await`, cancellation on early exit, `close(timeoutMs)`).
- Legacy ABI 6 SHM reader/writer and pool/memory-context exports, raw socket/connection injection, `requestShmThreshold` / `requestChunkSize`, and `C2IpcRouteNotFoundError` (plus unreleased intermediate ABI 7 and `C2IpcCallRejectedError`) are removed in favor of `C2IpcTransportError`, `C2CoreError`, `C2RouteConflictError` and `C2NativeError`.

## Notable fixes and performance

- **Windows Named Pipe stability:** Updated `mio` to `1.2.4` across all lockfiles, fixing a Windows Named Pipe use-after-free race confirmed via crash dump (`0xC0000005` during listener close / pipe disconnect; three earlier dump-less `0xC0000374` events remain separately tracked in the backlog).
- **Windows close & relay refusal delivery:** Server write/flush errors after peer close (`EPIPE`/`ECONNRESET` or Windows `109`/`232`) now defer the connection's first close reason to the reader (`peer_close_message` / `peer_eof`). Relays discard unread request bodies within a bounded deadline before sending pre-dispatch refusals so Windows clients receive the refusal instead of a connection reset.
- **Direct IPC shutdown ACK fence:** `'initiated'` becomes visible only after admission is closed on every server connection.
- **Held-response release & relay fixes:** Releasing a `HeldResult` releases its internal lock before running Python invalidators (preventing GIL/lock deadlocks with concurrent buffer exports); `c3 relay --bind ...:0` binds before building route state and advertises/prints the real port; relay route withdrawal mid-acquisition reports `ResourceNotFound` instead of `ResourceUnavailable`; abandoning an HTTP stream body releases `PullBody`'s and `drive_stream`'s `ReusableWindow` handles before cancelling upstream; large chunked payloads (>64 MiB), >64-entry custom Unix IPC roots, malformed control/registry responses, finite call slot release ordering and shared concurrent endpoint acquisition are all fixed.
- **Small-call latency note:** Moving to single-owner release with a dedicated per-connection writer task adds about **40–70 µs** to a 1-byte IPC call. In the four-platform paired benchmark comparing `b861f994` against the protocol-batch candidate `d646fc12` ([run 41444159385](https://github.com/Dsssyc/c-two/actions/runs/41444159385), [write fast-path experiment](../research/2026-11-02-ipc-write-fast-path-experiment.md)), 1-byte P50 ratios were **1.18–1.20×** (Linux), **1.18–1.21×** (Windows x64), **1.13×** (Windows ARM64) and **1.25–1.28×** (macOS) with throughput **0.83–0.90×**; 64 KiB buddy calls stayed within **0.97–1.06×** on Linux and Windows; and 4 MiB calls were **6–14% faster** on Linux and Windows (**0.99–1.07×** on macOS). Prefer batch reads or in-resource computation over fine-grained per-element RPCs.
